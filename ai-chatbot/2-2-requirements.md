# CB-2-2. 요구사항 (챗봇 RAG)

> C-FR/C-NFR 체계.

## CB-2-2.1 기능 요구사항 (C-FR)

| ID | 요구사항                                                                                                                                                                                                     | 상태                  |
| --- |----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|---------------------|
| **C-FR1** | 검색은 하이브리드다 — nori BM25(어휘) + kNN(의미) → RRF 융합. 종목·기간 메타필터가 양쪽에 공통 적용된다.                                                                                                                                  | 확정                  |
| **C-FR1b** | 뉴스 청크 검색은 **질의 당일 기준 최근 7일 이내** 기사로 한정한다(published_at 필터 고정). 예외 2: ① 용어(TERM) 청크는 기간 무관 ② NEWS 맥락 승격(C-FR5)은 기간 제한을 받지 않는다 — 사용자가 열어둔 옛 기사 질문이 무근거가 되지 않게. 색인은 전체 보존하고 검색 시점 필터로만 적용(기간 변경이 설정 수준이 되게). | 확정 (9/18 결정)        |
| **C-FR2** | 지식 원천은 **가공 뉴스 청크 + 용어 사전** 2원천이다. 용어 질문이 뉴스 검색 실패로 귀결되지 않는다.                                                                                                                                            | 확정 (노션 안에 용어 원천 보강) |
| **C-FR3** | 청크는 색인 전 **컨텍스트 맥락문**을 부착해 합본으로 색인한다(Contextual Retrieval). 표시·인용은 원문 청크로 한다.                                                                                                                            | 확정                  |
| **C-FR4** | 원문 제목+스니펫을 **검색 필드에 포함**한다(BM25 어휘 매칭용). 표시하지 않는다. 원문 전문 크롤링은 스코프 밖(§CB-2-2.3).                                                                                                                          | 확정                  |
| **C-FR5** | NEWS 맥락(newsId) 질의 시 해당 기사 청크를 1차 참고로 승격하고, (원천, 원천ID) 중복 제거 후 **rerank 통과분(0~20)** 으로 프롬프트를 조립한다 — 별도 상한 없음. | 확정 (9/19) |
| **C-FR6** | 답변에는 출처가 붙는다 — SSE `source` 이벤트 계약 유지.                                                                                                                                                                   | 확정                  |
| **C-FR7** | rerank 통과 청크가 **5개 이하면 저근거 모드** — 답변에 "관련 자료가 충분치 않다"는 언급을 포함하되 **"자료가 없다"고는 하지 않고** 일반 지식으로 보완해 답한다. 0건은 저근거의 극단 케이스로 동일 규칙(이때 `source` 빈 목록). 6개 이상이면 통상 근거 답변. 0건·저근거 발생은 로그·메트릭·트레이스에 기록. 계약 무변경. | 확정 (9/19) |
| **C-FR8** | RRF 결과에 **rerank(LLM 관련성 게이트)를 적용한다** — query 와 관련 있다고 판단된 청크만 통과(개수 가변). "확신 없으면 통과"(과필터 금지), 판정 불능 시 전체 통과. 프롬프트·통과 기준·지연 영향은 평가로 검증.                                                                  | 확정 (9/19) |
| **C-FR9** | 가드레일은 배치와 동일한 2단 파이프라ㅇ인(무조건 재작성 → LLM 판정 → 피드백 ≤2회)을 적용하며, **전송은 전 과정 통과 후에만** 한다. 대기 중에는 진행 단계 이벤트를 보낸다. 소진 시 실패 안내(검증 안 된 답변 전송 없음).                                                                   | 확정 (9/19, §CB-4-3.2) |

## CB-2-2.2 비기능 요구사항 (C-NFR)

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| **C-NFR1** | **답변 도달 지연 예산** — 검색(+rerank)→생성→재작성→판정이 전부 직렬이므로(C-FR9), 완성 답변 도달 p95 예산을 정하고 검증한다. 첫 진행 단계 이벤트는 즉시 발행. ❓목표치(예: p95 ≤ Ns) | 목표치만 결정 필요 |
| **C-NFR2** | PG = SSOT, ES = 파생 — ES 전소 시 PG 에서 전량 재색인으로 복구 가능해야 한다. | 확정 |
| **C-NFR3** | ES 장애가 챗봇 외 기능(수집·가공·색인 외 배치)에 영향을 주지 않는다. 챗봇 자체의 ES 장애 폴백: **장애 로그·메트릭을 남기고 무자료 일반 답변**(0건 폴백 C-FR7 과 동일 경로 — source 빈 목록, 사용자 오류 노출 없음). 컷오버(듀얼런) 기간에는 pgvector 폴백이 이를 대신할 수 있다. | 확정 (9/19) |
| **C-NFR4** | 임베딩 모델은 **text-embedding-3-large(3072)** 로 확정 — 비용 ~2배는 검색 품질 우선으로 수용, 컨텍스트 도입으로 전량 재임베딩은 어차피 발생. ADR 에 ADR-018 supersede 로 기록. 퀴즈 유사도는 small 유지(이원화 인지). | 확정 (9/19) |
| **C-NFR5** | 단계별 관측 — query, BM25/kNN/RRF/rerank 각 단계 청크, 생성 출력, 토큰, 지연을 기록한다(§CB-6). | 확정 |
| **C-NFR6** | 키·ES 자격증명은 환경변수/Secrets Manager 로만 (NFR-S1). | 확정 |
| **C-NFR7** | 컷오버는 듀얼런으로 한다 — **신규 청크 테이블 하나** 위에서 검색 구현만 2개(pgvector HNSW vs ES)를 두고, **검색만 `sttak.rag.store`(`pgvector`\|`es`) 플래그로 전환**한다. 문제 시 설정 복귀로 즉시 롤백. 안정화 후 구 검색 경로와 플래그를 **함께 제거**한다(전환기 한정 안전장치 — 영구 스위치 아님). | 확정 (플래그명 포함) |
| **C-NFR8** | 모든 프롬프트(컨텍스트 생성·rerank·챗 시스템)와 파라미터(k, RRF k, top-N)는 **평가셋 실측으로 확정**하고, 변경 시 재검증한다(AI-NFR7 준용). | 확정 |

## CB-2-2.3 명시적 아웃 오브 스코프

- **뉴스 원문 전문 크롤링** — 저작권·약관 리스크로 제외(기존 결정). 재론은 법적 확인+팀 결정
  선행이며 실험으로 정할 사안이 아님. 데이터 소스 한계(답변 디테일 상한)는 ADR 에 정직하게 명시
- 멀티홉·인과 그래프 (파킹 유지)
- 퀴즈 유사도의 ES 이관 (별도 후속 — `../ai-feature` VectorStore 구현 교체)
- 대화 세션 서버 저장 (계약 유지 — 클라이언트가 히스토리 전송)
