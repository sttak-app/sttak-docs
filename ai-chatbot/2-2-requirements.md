# CB-2-2. 요구사항 (챗봇 + 뉴스 AI)

각 기능은 해결하려는 문제, 입력, 출력, 필수 규칙 순서로 설명한다. 검색 개수(`k`), 융합
상수, 검색 기간과 같은 세부 값은 이 문서에서 고정하지 않는다. 평가 결과를 바탕으로 정하고
설정으로 조정한다.

## CB-2-2.1 기능 ① 뉴스 요약

**해결하려는 문제**: 전문 용어와 긴 문장으로 된 기사를 초보자도 이해할 수 있게 바꾼다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 기사 1건: 수집 API가 제공한 제목 + 스니펫 |
| 출력 | 쉬운 제목 + 한 줄 요약 + 3~5문장 상세 요약 + 용어 풀이 1~3개 |

정확한 필드명과 출력 예시는 `3-2-contract.md`의 [뉴스 요약 계약](./3-2-contract.md#cb-3-221-뉴스-요약)을 따른다.

**규칙 (N-FR)**

| ID | 요구사항 |
| --- | --- |
| N-FR1 | 기사에 없는 사실을 추가하지 않는다. 수치·날짜·회사명은 기사 그대로. |
| N-FR2 | 원문 문장을 그대로 복사하지 않고 내용을 다시 구성한다. |
| N-FR3 | 어려운 용어 1~3개에 풀이가 붙는다. |

## CB-2-2.2 기능 ② 뉴스 호재/악재 판단

**해결하려는 문제**: 해당 뉴스가 종목에 어떤 영향을 줄 수 있는지 방향과 근거를 함께
설명한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 기사 1건(제목+스니펫) + 기사에 연결된 종목 목록 |
| 출력 | 종목별 영향 방향(POSITIVE/NEGATIVE/NEUTRAL) + 근거 문장 + 근거 항목 |

정확한 필드명과 출력 예시는 `3-2-contract.md`의 [뉴스 호재·악재 판단 계약](./3-2-contract.md#cb-3-222-뉴스-호재악재-판단)을 따른다.

**규칙 (N-FR)**

| ID | 요구사항 |
| --- | --- |
| N-FR4 | 기사에 담긴 사실만 근거로 삼는다. 투자심리 단독 근거 금지. |
| N-FR5 | 영향이 작더라도 방향을 판단할 수 있으면 `POSITIVE` 또는 `NEGATIVE`로 분류한다. 방향을 정할 근거가 없을 때만 `NEUTRAL`로 분류한다. |
| N-FR6 | 요약(①)과 판단(②)은 서로 독립된 트랙으로 처리한다. 각각 별도의 프롬프트와 검증을 거친 뒤 결과를 합쳐 저장한다. 한 트랙이라도 실패하면 기사 전체를 다시 처리하며 일부 결과만 저장하지 않는다. |
| N-FR7 | 검증(재생성) 과정에서 판단 라벨(`stockCode` + `sentiment`)이 바뀌지 않도록 코드로 잠근다. |

## CB-2-2.3 기능 ③ 챗봇 답변(RAG)

**해결하려는 문제**: 뉴스를 읽다가 생긴 질문에 가공 뉴스와 용어 사전을 근거로 답하고,
출처를 함께 제공한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 질문 + 대화 히스토리(클라이언트 전송) + 선택 맥락(보던 기사 newsId 등) + 검색 통과 청크 |
| 출력 | 답변 텍스트 + 청크의 원천(기사/용어)을 역참조한 출처 목록 |

세부 호출별 입출력은 `3-2-contract.md`의 [챗봇 질의 호출 계약](./3-2-contract.md#cb-3-23-챗봇-질의-호출)을 따른다.

**규칙 (C-FR)**

| ID | 요구사항 |
| --- | --- |
| C-FR1 | 어휘 검색(BM25)과 의미 검색(벡터)을 병렬로 실행한 뒤 RRF로 결과를 합친다. 종목과 기간 필터는 두 검색에 똑같이 적용한다. **검색 결과가 0건이어도 실패로 처리하지 않는다.** 한쪽에만 결과가 있으면 해당 결과로 다음 단계를 진행한다. 양쪽 모두 결과가 없고 C-FR5에 따라 우선 제공할 기사 청크도 없으면 C-FR6의 일반 지식 답변으로 넘어간다. |
| C-FR2 | 챗봇은 **가공 뉴스 청크와 용어 사전**을 지식 원천으로 사용한다. 뉴스 검색 결과가 없어도 용어 질문에는 답할 수 있어야 한다. |
| C-FR3 | 뉴스 청크는 최근 기사를 중심으로 검색하도록 기간을 제한한다. 용어 청크와 NEWS 승격은 예외로 둔다. 전체 색인은 유지하고 검색할 때만 기간 필터를 적용한다. |
| C-FR4 | 합쳐진 검색 결과에 **rerank(LLM 관련성 필터)**를 적용한다. 질문과 관련 있다고 판단한 청크만 통과시키며, 통과 개수는 달라질 수 있다. 지나치게 많이 거르지 않도록 판단이 어려우면 통과시킨다. |
| C-FR5 | 사용자가 기사를 보다가 질문하면(`newsId` 맥락), 해당 기사 청크를 우선 참고 자료로 올린다. |
| C-FR6 | 검색과 NEWS 승격을 거친 최종 참고 자료가 **0건이면 LLM의 일반 지식으로 답변**하고 출처는 빈 목록으로 반환한다. 참고 자료가 적으면 관련 자료가 충분하지 않다고 알리고 일반 지식으로 내용을 보완한다. 이때 자료가 없다고 단정하거나 답변을 거부하지 않는다. |
| C-FR7 | 답변에는 출처가 붙는다. 출처는 실제로 참고한(통과한) 청크의 원천에서만 나온다. |
| C-FR8 | 생성된 답변은 전송 전에 검증 파이프라인(재생성 → 검수)을 통과한다. 검증 전 텍스트는 사용자에게 나가지 않는다. |

## CB-2-2.4 공통 규칙 (G-FR)

| ID | 요구사항 |
| --- | --- |
| G-FR1 | 모든 AI 결과물은 사용자에게 제공하기 전에 가드레일을 거친다. 항상 한 번 재생성한 뒤 후보 탐지 힌트를 포함해 검수하고, 위반이 있으면 피드백을 반영해 다시 생성한다. 재시도 상한 안에 검수를 통과한 결과만 저장하거나 전송하며, 횟수를 모두 소진하면 사용하지 않는다. |
| G-FR2 | 투자 권유 표현의 위반 범주와 위반으로 보지 않을 사례(교육 목적의 언급, 부정 문맥, 인용, 사실 보도)를 검증 자산으로 관리한다. 목록을 바꾸면 평가셋을 다시 검증한다. |
| G-FR3 | 기사처럼 외부에서 가져온 텍스트가 프롬프트에 들어갈 때는 프롬프트 주입 방어를 적용한다. |

## CB-2-2.5 비기능 요구사항 (NFR)

| ID | 요구사항 |
| --- | --- |
| NFR1 | 뉴스 가공과 색인은 배치(경로 B), 챗봇 질의는 실시간(경로 A)으로 처리한다. 피드를 조회할 때는 LLM을 호출하지 않는다. |
| NFR2 | 챗봇 응답은 사용자가 기다리는 동안 처리되므로 검색부터 생성, 검증을 마치고 답변이 도착할 때까지의 지연 예산을 정해 검증한다. 처리 중에는 진행 상태를 알린다. |
| NFR3 | 질문 임베딩과 청크 임베딩은 같은 모델을 쓴다(벡터 공간 일치). |
| NFR4 | 검색 인덱스는 원본 데이터로 만든 파생물이며, 원본 저장소의 데이터를 모두 다시 색인해 복구할 수 있어야 한다. |
| NFR5 | 검색 인프라 장애가 챗봇 외 기능에 영향을 주지 않아야 한다. 챗봇은 검색 자료 없이 답하는 C-FR6의 0건 경로로 전환한다. |
| NFR6 | 프롬프트와 검색 파라미터는 평가셋 결과를 바탕으로 정하고, 변경하면 다시 검증한다. |
| NFR7 | 질문, 검색 단계별 청크, 생성 결과, 토큰 사용량, 지연 시간을 기록한다. 자세한 내용은 `6-observability`에서 다룬다. |
| NFR8 | API 키와 검색 인프라 자격증명은 환경 변수나 시크릿 저장소를 통해서만 주입한다. |
