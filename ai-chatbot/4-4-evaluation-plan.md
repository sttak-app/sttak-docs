# CB-4-4. 평가 계획 (결정 항목 카탈로그)

> 원칙: 설계 논쟁은 실측으로 끝낸다 (`../ai-feature/4-4` 준용). **평가셋이 구현보다 먼저다** —
> §4-1~4-3 의 ❓ 대부분이 여기서 답을 얻는다.

## CB-4-4.1 검색 평가셋 — 만들 것

- ❓ 규모·구성(세트를 몇 건이나, 유형별 몇 개씩 준비할지) — 유형 커버 필수:
  ① 사건 질문("무슨 일이야") ② 종목 영향 질문("왜 호재야") ③ 용어 질문("PER?")
  ④ **기사 표현 그대로 질문**("유상증자 발표했다던데" — BM25 이득 검증용)
  ⑤ 정답 없는 질문(0건 폴백·저근거 행동 검증용)
- 지표: **recall@k 확정** — 정답 청크가 상위 k 후보 안에 든 비율(k=20 = 후보 수와 정합, rerank 입력 기준). 검색 실패율(1 − recall@20)로도 병기 — Contextual Retrieval 문헌 지표와 직접 비교 가능. 순위 민감 지표(MRR)는 미채택: 최종 선별을 rerank 가 하므로 "후보 안에 들었냐"가 본질
- 라벨링·채점: **Fable 수행 확정** — 기존 평가(SCRUM-73)와 동일 방식: 정답 라벨·유도 세트 생성과 채점을 Fable 이 하고, 경계 사례만 사람 검수. luna(피평가)와 평가자(Fable) 분리 유지

## CB-4-4.2 실험 매트릭스 — 돌릴 것

| 축 | 비교 | 답하는 질문 |
| --- | --- | --- |
| 저장소 | 현행 pgvector vs ES 하이브리드 vs ES+컨텍스추얼 (3단) | 전환·컨텍스추얼 각각의 근거 |
| 청크 분할 | 1기사 1청크 vs 요약+종목판단 분리 | §CB-4-1.1 |

## CB-4-4.3 답변 품질·가드레일 평가 — 만들 것

- 답변 루브릭 — **평가 착수 시 작성** (방식 확정: 기존 기능 루브릭 준용, 축 = 근거 충실·환각·출처 정확·톤·저근거 행동, 채점 Fable)
- 챗봇용 위반 유도 세트 — **평가 착수 시 작성** (목적 확정: 챗 파이프라인(재작성·판정+CHAT_SLOT) 제거율·오탐 검증 — 배치 실측은 배치 프롬프트 기준이라 챗 문안으로 재실측)
- 지연: 시나리오별 p95 (검색만 / +rerank / 완성 답변 도달까지 — 생성+재작성+판정 직렬 포함) — C-NFR1 예산 검증
