# CB-5-1. 테스트 (결정 항목 카탈로그)

> 원칙은 `../ai-feature/5-1` 공유 — LLM·ES 는 실물 호출 없이, 판단 로직은 실코드로.
> 품질 자체는 평가(§CB-4-4) 몫, 테스트는 회귀 방지 몫.

## CB-5-1.1 정할 것 — 레이어별 대상

| 레이어 | 대상 | 방식 (안) | 정할 것 |
| --- | --- | --- | --- |
| 단위 | RRF 융합 | 순수 함수 — 순위 시나리오 고정 검증 | 구현 확정 후 케이스 |
| 단위 | 검색 어댑터 | ES 클라이언트 목 — 쿼리 DSL 형태(필터·kNN·BM25 결합) assert | ❓쿼리 스냅샷 vs 요소 검증 |
| 단위 | 색인 어댑터 | 목 — 문서 매핑·합본 필드 조립 검증 | |
| 단위 | 컨텍스트 생성 스텝 | LLM 목 — 멱등(대상 선정)·실패 격리 | |
| 단위 | (채택 시) rerank | LLM 목 — 통과 기준·판정 불능=통과 | 채택 결정 후 |
| 통합 | 색인 파이프라인 E2E | ❓ **Testcontainers ES/OpenSearch** — nori 포함 이미지 필요 (H2 금지 원칙의 ES 판. 이미지·기동 비용 검증 선행) | 도입 여부·이미지 |
| 통합 | 검색 E2E | 위 컨테이너에 시드 색인 → 하이브리드 질의 → 순위 검증 | 대표 시나리오 몇 개로 한정 |
| 계약 | 챗 Service | 검색 포트 목 — 0건 폴백·NEWS 승격·중복 제거·최대 N | C-FR7 결정 반영 |

## CB-5-1.2 반드시 있어야 하는 것 (지금 확정)

1. **듀얼런 스위치 테스트** — 플래그별로 올바른 구현이 선택되는지 (컷오버 안전망)
2. **0건 폴백 테스트** — C-FR7 결정 그대로의 행동 (용어 질문이 거부되지 않는 것 포함)
3. nori 토큰화 검증은 테스트가 아니라 **평가 선행 작업** — CI 에 넣지 않음 (분석기 설정 변경
   시 수동 재검증 절차로)

## CB-5-1.3 하지 않는 것

- 실 ES 클러스터·실 LLM 호출 테스트 (비용·비결정성)
- 검색 품질 assert (top-N 에 뭐가 오는가) — 평가 몫
- 프롬프트 전문 스냅샷
