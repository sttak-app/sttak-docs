# CB-1. 챗봇 배경과 문제 정의

> 본 디렉터리(`docs/specs/ai-chatbot/`)는 챗봇("AI에게 묻기") **RAG 개편**의 스펙이다.
> 설계 원본: 노션 "CHATBOT PIPE LINE" + 검토 페이지. 배치 AI 5기능은 `../ai-feature/` 참조.
> 상태: **설계 단계** — §4·§5 는 구현 확정이 아니라 "결정해야 할 항목"의 카탈로그다.

## CB-1.1 챗봇이 하는 일

초보 투자자의 질문("이 뉴스가 왜 호재야?", "PER가 뭐야?")에 **우리 지식(가공 뉴스·용어)을
근거로, 출처를 붙여** 답한다(FR-G1~G3, U19). 근거가 담보되지 않는 자유 생성이 아니라
검색-증강 생성(RAG)이며, 실시간 SSE 스트리밍 경로(A)에서 동작한다 — 배치 5기능과 달리
**사용자가 기다리는 중**이라는 제약이 모든 설계를 지배한다.

## CB-1.2 왜 개편하는가 — 현행(ADR-016)의 한계

| 현행 구성 | 한계 |
| --- | --- |
| pgvector 코사인 kNN | 의미 검색은 됨 |
| SQL 메타필터 (stock_codes·published_at) | 유지 가치 있음 |
| pg_trgm 용어 매칭 | 용어 사전의 짧은 명사만 — **본문 어휘 검색이 없음** |
| (본문 BM25 없음) | RDS PG 에 한국어 형태소 분석기 부재 → 기사 표현 그대로 묻는 질문("유상증자 발표했다던데?")이 빗나감 |

개편 = **Elasticsearch/OpenSearch 하이브리드**: nori 형태소 BM25(어휘) + kNN(의미) + RRF 융합
+ Contextual Retrieval(색인 시점 맥락문 부착). ADR-016 의 정직한 절충("한국어 FTS 부재")을
정면으로 해소하는 것이 개편의 존재 이유다.

## CB-1.3 도메인 용어

| 용어 | 정의 |
| --- | --- |
| **청크 (Chunk)** | 검색·인용의 최소 단위. 가공 뉴스에서 조립 — 분할 단위는 결정 사항(§CB-4-1) |
| **컨텍스트 (Context)** | 색인 전에 LLM 이 청크에 붙이는 50~100토큰 맥락문("이 청크는 {날짜} {기사} 중 …"). 검색 필드에만 합본, 표시는 원문 청크 (Contextual Retrieval) |
| **BM25** | 어휘(단어 빈도) 기반 검색 — nori 형태소 분석 전제. TF-IDF 계열 |
| **kNN** | 임베딩 벡터 최근접 — 의미 기반 검색 |
| **RRF (Reciprocal Rank Fusion)** | BM25·kNN 두 순위를 1/(k+rank) 합산으로 융합. 점수 정규화 불요 |
| **rerank** | 융합 결과를 LLM 이 query 와의 관련성으로 판정해 **관련 있다고 판단한 것만 남기는 필터** — 상위 N개를 자르는 방식이 아니라 개수가 가변(0~전부). **채택 여부 자체가 결정 사항**(지연 비용) |
| **SSOT / 파생 인덱스** | 원본은 PG, ES 는 언제든 재색인으로 복구 가능한 사본 — 정합성·백업 전략의 대전제 |
| **듀얼런 (Dual-run)** | 컷오버 기법 — 색인은 양쪽(pgvector·ES), 검색은 플래그로 전환 |
| **드리프트 (Drift)** | PG 와 ES 의 내용 불일치. 멱등 색인 + 건수 비교 메트릭으로 감시 |

## CB-1.4 확정된 것 / 결정 대기인 것

**확정 (설계 합의)**
- ES/OpenSearch 하이브리드 (nori BM25 + kNN + RRF) + Contextual Retrieval
- 저장: PG 먼저(SSOT, 신규 청크 테이블 — 기존 운영 테이블 무변경) → ES 반영
- LLM 은 luna 단일 (ADR-032 정합), RRF 는 직접 구현(수식 수준)
- 단계별 로깅 (query → BM25/kNN/RRF/rerank 청크 → 생성 출력 → 토큰·지연)
- 뉴스 검색 대상은 **질의 당일 기준 최근 7일** 한정 (용어·NEWS 승격 예외 — C-FR1b)

**결정 대기 (구현 착수 전 필요) — 상세는 각 절**
1. 뉴스 **원문 크롤링** 여부 — 저작권·약관 리스크로 기존 결정은 제외. 재론하려면 법적 확인 선행 (§CB-2-2 스코프)
2. **스트리밍 × 가드레일** — 2단 파이프라인은 완성 응답 전제라 SSE 와 상극. 3안 중 택1 (§CB-4-3)
3. 검색 0건 시 **폴백 계약** — 현행 "일반 개념 설명 폴백" vs 노션 안 "기사 못 찾음 안내" (§CB-3-2)
4. 임베딩 모델 — 노션 안 text-embedding-3-**large** vs 현행 small: 근거 실측 필요 (§CB-4-1)
5. rerank 채택 여부 — 지연·비용 vs 정밀도, 평가로 결정 (§CB-4-2)
