# CB-1. 배경과 문제 정의 (챗봇 + 뉴스 AI)

이 디렉터리(`docs/specs/ai-chatbot/`)에서는 뉴스 AI 파이프라인(요약·호재/악재 판단)과
챗봇("AI에게 묻기", RAG)을 다룬다. 뉴스 파이프라인이 가공한 뉴스를 만들고, 챗봇은 그
데이터를 검색해 답변하므로 두 기능을 함께 정의한다. 뉴스와 직접 관련이 없는 배치 AI 기능인
퀴즈, 차트 신호 해설, 매매 회고는 `../ai-feature/`에서 설명한다.

## CB-1.1 해결하려는 문제

sTTak은 20~30대 초보 투자자를 위한 주식 학습 서비스다. 새로운 뉴스가 계속 들어오지만
초보자가 이해하기에는 어렵고, 기사를 읽은 뒤에도 여러 궁금증이 남는다. 이 문제를 다음 세
기능으로 해결한다.

| 문제 | AI가 하는 일 | 제공 방식 |
| --- | --- | --- |
| 전문 용어와 긴 문장 때문에 기사를 이해하기 어렵다 | **뉴스 요약**: 쉬운 제목, 한 줄 요약, 상세 요약, 용어 풀이 제공 | 배치 생성 → 저장 → 피드 조회 |
| "내 종목엔 뭐가 되는 건지" 해석이 없다 | **호재/악재 판단**: 종목별 POSITIVE/NEGATIVE/NEUTRAL + 근거 | 배치 생성 → 저장 → 피드 조회 |
| 기사를 읽다가 생긴 질문("이게 왜 호재야?", "PER이 뭐야?")을 바로 물어보기 어렵다 | **챗봇**: 가공 뉴스와 용어 사전을 검색하고 근거와 출처를 포함해 답변(RAG) | 실시간 질의응답(SSE) |

sTTak은 학습 서비스이므로 모든 AI 생성물에 투자 권유로 읽힐 수 있는 표현이 들어가면 안
된다. 생성물은 사용자에게 제공하기 전에 가드레일 검증(재생성 → 검수)을 거친다.

## CB-1.2 뉴스 데이터의 흐름

```
뉴스 수집 → AI 가공(요약·판단) → 저장 ─→ 피드 (읽기 전용 조회)
                                   └→ 청크 조립 → 색인 → 챗봇 검색 대상
```

- 챗봇은 가공된 뉴스를 바탕으로 답한다. 검색 성능이 좋아도 뉴스 가공 결과가 부실하면 좋은
  답변을 만들 수 없다.
- 요약 형식이나 판단 근거 같은 가공 규칙이 바뀌면 챗봇이 참고하는 지식도 달라진다. 따라서
  뉴스 가공과 챗봇은 함께 설계하고 평가한다.
- 이 문서에서 말하는 뉴스 원문은 수집 API가 제공하는 제목과 스니펫이다. 기사 전문은
  크롤링하지 않으므로 요약, 검색, 답변이 다룰 수 있는 정보도 이 범위로 제한된다.

## CB-1.3 도메인 용어

아래는 문서에서 혼동하기 쉬운 용어를 정리한 표다. `업계`는 일반적으로 쓰이는 표준 용어,
`sTTak`은 이 저장소에서 정한 의미로 사용하는 용어를 뜻한다.

### 검색·색인 (챗봇)

| 용어 | 정의 | 구분 |
| --- | --- | --- |
| **RAG (Retrieval-Augmented Generation)** | 답변 생성 전에 관련 자료를 검색해 프롬프트에 넣는 방식. 근거 없는 자유 생성과 대비된다 | 업계 |
| **청크 (Chunk)** | 검색과 인용에 사용하는 최소 단위 텍스트. 기사 한 건의 가공 결과 전체를 한 청크로 만들고, 용어도 한 건을 한 청크로 만든다. 일반적인 청킹과 달리 문서를 더 작게 나누지 않는다 | 업계(단위는 sTTak 결정) |
| **임베딩 (Embedding)** | 텍스트를 의미 공간의 벡터로 변환한 것. 질문 임베딩과 청크 임베딩은 **반드시 같은 모델**이어야 거리 비교가 성립한다 | 업계 |
| **벡터 검색 / kNN** | 질문 임베딩과 가장 가까운(k-Nearest Neighbors) 청크를 찾는 의미 기반 검색. "삼전 반도체 어때" ↔ "삼성전자 메모리 업황" 처럼 표현이 달라도 잡는다 | 업계 |
| **BM25** | 단어 빈도 기반 어휘 검색 알고리즘. 기사 표현 그대로 묻는 질문("유상증자 발표했다던데")을 잡는다. 한국어에서는 형태소 분석이 전제다 | 업계 |
| **형태소 분석 (nori)** | 한국어 문장을 검색 가능한 단위로 나누는 작업. nori는 Elasticsearch의 한국어 분석기다 | 업계 |
| **하이브리드 검색** | 어휘 검색(BM25)과 의미 검색(벡터)을 동시에 실행한 뒤 결과를 합치는 방식. 한쪽 검색이 놓친 질문을 다른 쪽에서 보완할 수 있다 | 업계 |
| **RRF (Reciprocal Rank Fusion)** | 두 검색의 순위를 1/(k+rank) 합산으로 융합하는 표준 기법. 점수 체계가 다른 두 검색을 정규화 없이 결합한다 | 업계 |
| **rerank** | 보통은 검색 결과를 다시 정렬해 상위 N개를 고르는 뜻으로 쓰인다. sTTak에서는 관련성 필터를 뜻하며, LLM이 질문과 관련 있다고 판단한 청크만 통과시킨다. 통과하는 청크 수는 0개부터 전체까지 달라질 수 있다 | 업계(사용 방식은 sTTak) |
| **색인 (Indexing)** | 청크를 검색 엔진에 등록하는 것. 우리는 BM25 인덱스와 벡터 인덱스에 이중 색인한다 | 업계 |
| **top-k** | 검색이 돌려주는 상위 k 건. 구체 값은 설계가 아니라 평가로 정한다 | 업계 |
| **NEWS 승격** | 사용자가 특정 기사를 보다가 질문하면(`newsId` 맥락), 검색 순위와 관계없이 해당 기사의 청크를 우선 참고 자료로 올리는 것 | sTTak |
| **용어(TERM) 청크** | 용어 사전에서 만든 청크. 뉴스 청크와 별도로 검색해 "PER이 뭐야" 같은 질문도 답할 수 있게 한다 | sTTak |
| **저근거 모드** | 최종 참고 자료가 적을 때 자료가 충분하지 않다고 알리고 일반 지식으로 답변을 보완하는 방식. 최종 참고 자료가 없으면 출처는 빈 목록으로 반환한다 | sTTak |

### 뉴스 가공 (배치)

| 용어 | 정의 | 구분 |
| --- | --- | --- |
| **가공 (Enrichment)** | 수집된 뉴스에 요약·판단 두 트랙을 실행해 학습용 콘텐츠로 만드는 배치 단계 | sTTak |
| **호재/악재 판단 (Sentiment)** | 기사 한 건이 특정 종목에 미치는 영향을 POSITIVE/NEGATIVE/NEUTRAL로 나누고 근거를 제시하는 것. 일반적인 감성 분석과 달리 **종목에 미치는 영향의 방향**을 판단한다 | sTTak(용어는 업계에서 유래) |
| **트랙 (Track)** | 요약과 판단을 각각 처리하는 독립 경로. 프롬프트와 검증 과정은 분리하지만, 둘 중 하나라도 실패하면 기사 전체를 다시 처리한다 | sTTak |
| **whyPoints** | 판단 근거를 항목별로 나눈 목록. 문장으로 작성하는 `reason`과는 별개다 | sTTak |
| **청크 조립** | 요약과 종목 판단을 기사 단위 검색 텍스트 하나로 합치는 작업. 문서를 나누는 것이 아니라 기사 한 건을 한 청크로 합친다 | sTTak |

### 검증 (가드레일)

| 용어 | 정의 | 구분 |
| --- | --- | --- |
| **가드레일 (Guardrail)** | AI 출력이 사용자에게 닿기 전 통과해야 하는 검증 장치의 총칭. 업계에서도 같은 뜻으로 쓴다 | 업계 |
| **재생성 (= 무조건 재작성, Rewrite)** | 1차 생성물을 금지 표현과 형식 기준에 맞춰 LLM이 다시 쓰는 단계. 위반 여부와 관계없이 항상 수행한다 | sTTak |
| **검수 (= 판정, Judge)** | LLM이 재생성 결과의 위반 여부를 최종 판단하는 단계. 위반이 있으면 피드백을 추가해 재생성 단계로 돌려보낸다. 반복 횟수에는 상한이 있다 | sTTak |
| **후보 탐지** | 정규식으로 위반이 의심되는 표현을 찾아 검수 프롬프트에 힌트로 넣는 과정. 최종 판정은 아니며, 패턴에 걸린 표현이 검토 대상에서 빠지지 않도록 돕는다 | sTTak |
| **코드 잠금 (Code Lock)** | 재생성 과정에서 바뀌면 안 되는 구조화 값(예: 판단 라벨)이 그대로인지 코드로 한 번 더 확인하는 장치 | sTTak |
| **소진 (Exhausted)** | 재생성 횟수를 모두 사용했는데도 위반이 남아 있는 상태. 이 결과는 저장하거나 전송하지 않는다 | sTTak |
| **오탐 (False Positive)** | 교육 목적의 언급, 부정 문맥, 사실 보도처럼 정상적인 문장을 위반으로 잘못 판단하는 것. 가드레일 품질을 판단하는 주요 지표다 | 업계 |
| **refusal (응답 거부)** | LLM이 답변 생성을 거부하는 응답 유형 | 업계 |
| **프롬프트 주입 (Prompt Injection)** | 입력 데이터에 지시문을 섞어 LLM을 조종하려는 공격. 기사처럼 외부에서 가져온 텍스트가 프롬프트에 들어가는 모든 지점에 방어가 필요하다 | 업계 |

### 실행 구조

| 용어 | 정의 | 구분 |
| --- | --- | --- |
| **경로 A / 경로 B** | 서버의 두 가지 처리 경로. A는 사용자 요청을 처리하는 실시간 경로이고, B는 배치 경로다. 뉴스 가공과 색인은 B, 챗봇 질의는 A에서 처리한다 | sTTak |
| **SSE (Server-Sent Events)** | 서버가 한 연결로 이벤트를 흘려보내는 HTTP 스트리밍 방식. 챗봇 응답 채널 | 업계 |
| **SSOT (Single Source of Truth)** | 데이터를 판단할 때 기준으로 삼는 단일 원본. 청크의 원본은 PostgreSQL에 보관하며, 검색 인덱스는 이 데이터로 언제든 다시 만들 수 있다 | 업계 |
| **멱등 (Idempotent)** | 같은 작업을 여러 번 수행해도 결과가 같은 성질. 배치 재실행 안전성의 근거 | 업계 |
