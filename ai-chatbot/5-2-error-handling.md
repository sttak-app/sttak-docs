# CB-5-2. 에러 처리 (챗봇 + 뉴스 AI)

예외 계층과 HTTP 매핑은 `../5-2-error-handling.md`를 따른다. 여기서는 AI 처리 과정에서
발생하는 실패만 다룬다. 챗봇은 실시간으로 동작하므로 장애가 사용자에게 바로 보이며, 배치
기능처럼 다음 회차에서 다시 시도할 수 없다.

## CB-5-2.1 실패 시 통과(fail-open)와 차단(fail-closed)의 경계

검증 시스템이 정상적으로 동작하지 않을 때 결과를 통과시킬지 차단할지 미리 정한다. 정상
답변을 막는 피해와 위반 답변을 보내는 피해를 비교해 결정한다.

| 상황 | 방향 | 이유 |
| --- | --- | --- |
| 검수 호출 또는 응답 파싱 실패 | **통과**(fail-open) | 검증 시스템의 장애로 정상 답변을 막는 피해가 더 크다 |
| 검수 refusal(응답 거부) | **반려**(fail-closed) | 단순히 판단이 어려운 상황이 아니라 입력 이상 신호로 본다. 재생성과 검수가 모두 실패해 검증하지 않은 원문이 전송되는 경로를 막는다 |
| 재생성 호출 실패 | 원문을 유지하고 검수 진행 | 검수가 마지막 차단 단계 역할을 한다 |
| rerank 판정 불능 | 모든 청크 통과 | 검색 보조 단계의 장애가 전체 답변 실패로 이어지지 않게 한다 |

## CB-5-2.2 챗봇의 상황별 처리

| 상황 | 처리 |
| --- | --- |
| 검색 결과 없음(장애 아님) | **오류로 처리하지 않고 다음 단계로 진행한다.** 한쪽에만 결과가 있으면 RRF를 생략하고 해당 결과로 rerank를 수행한다. 양쪽 모두 결과가 없으면 RRF와 rerank를 생략한다. 이때 NEWS 승격 청크가 있으면 참고 자료로 사용하고, 없으면 일반 지식 답변을 생성한다(C-FR6, `4-2`). 검색 호출 자체가 실패한 장애와 구분한다 |
| 검색 인프라 장애 또는 타임아웃 | 장애 로그와 메트릭을 남기고, 검색 결과가 없는 경우와 같은 경로를 사용해 일반 지식으로 답한다. 사용자에게 시스템 오류를 노출하지 않고 일반적인 설명을 제공한다. 듀얼런 기간에는 pgvector 대체 검색을 사용할 수 있다. 검색 타임아웃은 지연 예산(NFR2) 안에서 정한다 |
| 질문 임베딩 실패 | **한 번 재시도**한 뒤에도 실패하면 다시 질문해 달라고 안내하고 종료한다. 어휘 검색만으로 답하면 하이브리드 검색을 전제로 한 품질을 보장하기 어려우므로 재질문을 요청한다 |
| 생성·재생성·검수 호출 실패 | 지수 백오프로 3회 재시도한 뒤에도 실패하면 실패 안내 이벤트를 보낸다. 검증하지 않은 답변은 전송하지 않는다 |
| 가드레일 소진(피드백 2회 후에도 위반이 남은 경우) | 실패 안내 이벤트를 보내고 답변은 전송하지 않는다. 배치의 대체 처리와 같은 원칙을 적용한다 |

## CB-5-2.3 뉴스 가공·색인의 상황별 처리

| 상황 | 처리 |
| --- | --- |
| 가공 실패(한쪽이라도 실패) | 현재 기사 상태를 유지하고 다음 회차에서 기사 전체를 다시 처리한다. 일부 결과만 저장하지 않는다 |
| 판단 라벨 잠금 위반 | 데이터가 잘못 저장되지 않도록 해당 기사 결과를 반려한다 |
| 색인 실패 | 해당 데이터만 실패로 처리하고 다음 실행에서 멱등하게 다시 색인한다 |
| 검색 인프라 지속 장애 | 색인 대기 작업이 쌓이는 것을 허용하고 경보를 보낸다(`6`). 뉴스 수집과 가공은 계속 진행한다 |

## CB-5-2.4 격리 규약

1. 검색 인프라에는 챗봇 검색과 색인 단계만 의존한다. 뉴스 수집과 가공을 포함한 다른 배치는
   검색 인프라 상태와 관계없이 동작한다(NFR5).
2. 색인 단계가 실패해도 앞에서 저장한 뉴스 가공 결과는 되돌리지 않는다.
3. 검색이나 검증이 실패해도 응답 연결을 갑자기 끊지 않고 실패 안내를 보낸 뒤 정상 종료한다.

## CB-5-2.5 로그 규약

- 로그에는 질문 ID, 기사 ID, 청크 ID 같은 식별자를 중심으로 남긴다. 본문은 관측 시스템(`6`)에서
  관리하고 로그에는 중복해서 기록하지 않는다.
- 검색 실패는 어느 단계(BM25/벡터/RRF/rerank)인지 식별 가능하게 남긴다.
- API 키·검색 인프라 자격증명은 어떤 로그·예외 메시지에도 싣지 않는다.
