# CB-5-2. 에러 처리 (결정 항목 카탈로그)

> 계층·격리 원칙은 `../5-2-error-handling.md`·`../ai-feature/5-2` 공유. 챗봇 특유는
> **실시간 경로의 장애가 사용자에게 즉시 보인다**는 점 — 배치의 "다음 회차 재시도"가 없다.

## CB-5-2.1 에러 분류와 처리 방향 (안 — 결정 반영해 확정)

| 분류 | 처리 (안) | 정할 것 |
| --- | --- | --- |
| ES 검색 실패/타임아웃 | ❓ C-NFR3 폴백 결정 반영 — 컷오버기 pgvector 폴백 권장, 이후 (a)오류 안내 (b)무자료 답변 | 폴백 정책 + 검색 타임아웃 값(지연 예산 안) |
| 질문 임베딩 실패 | BM25 단독으로 진행(부분 성공) vs 전체 실패 ❓ | 부분 성공 허용 여부 |
| rerank 실패 (채택 시) | 통과 — RRF 결과 그대로 사용 (fail-open) | 확정 |
| 생성(스트림) 실패 | 현행 SSE 오류 처리 유지 | 유지 |
| 가드레일 위반 (방식별) | (b)안: 철회 이벤트 / (c)안: 후보 탐지 시 행동 ❓ | §CB-4-3.2 결정 후 |
| 색인 실패 (배치) | 해당 건만 실패 → 다음 회차 (배치 원칙 그대로) | 확정 |
| ES 클러스터 장애 (지속) | 색인 백로그 누적 수용 + 경보(§CB-6). 챗봇은 위 폴백 | 확정 골격 |

## CB-5-2.2 격리 규약 (확정)

1. ES 는 챗봇 검색·색인 스텝만 의존 — 수집·가공·타 배치는 ES 상태와 무관하게 동작
2. 색인 스텝 실패가 선행 스텝(가공) 커밋을 되돌리지 않는다
3. 검색 실패가 SSE 연결 자체를 깨지 않는다 — 폴백 응답으로 정상 종료

## CB-5-2.3 로그 규약

- `../ai-feature/5-2` 준용: 식별자 중심, 본문은 관측(§CB-6) 몫, 키·자격증명 금지
- 검색 단계 실패는 어느 단계(BM25/kNN/RRF/rerank)인지 식별 가능하게
