# CB-5-2. 에러 처리 (결정 항목 카탈로그)

> 계층·격리 원칙은 `../5-2-error-handling.md`·`../ai-feature/5-2` 공유. 챗봇 특유는
> **실시간 경로의 장애가 사용자에게 즉시 보인다**는 점 — 배치의 "다음 회차 재시도"가 없다.

## CB-5-2.1 에러 분류와 처리 방향 (안 — 결정 반영해 확정)

| 분류 | 처리 (안) | 정할 것 |
| --- | --- | --- |
| ES 검색 실패/타임아웃 | **장애 로그·메트릭 + 무자료 일반 답변** (C-NFR3 — 0건 경로 재사용). 듀얼런 기간엔 pgvector 폴백 우선 | 검색 타임아웃 값(지연 예산 안)만 결정 |
| 질문 임베딩 실패 | **재시도 1회 → 그래도 실패 시 "다시 질문해 달라" 안내로 종료 (확정 9/19)** — BM25 단독 진행(부분 성공) 미채택: 하이브리드 전제가 깨진 반쪽 검색 결과로 답하기보다 재질문이 정직 | 확정 |
| rerank 실패 | 통과 — RRF 결과 그대로 사용 (fail-open) | 확정 |
| 생성·재작성·판정 실패 | 재시도(ADR-014) 소진 시 실패 안내 이벤트 — 검증 안 된 텍스트 전송 없음 (C-FR9) | 확정 |
| 가드레일 소진 (피드백 2회 후 위반 잔존) | 실패 안내 이벤트 — 답변 미전송 (배치의 폴백과 동일 원칙) | 확정 (C-FR9) |
| 색인 실패 (배치) | 해당 건만 실패 → 다음 회차 (배치 원칙 그대로) | 확정 |
| ES 클러스터 장애 (지속) | 색인 백로그 누적 수용 + 경보(§CB-6). 챗봇은 위 폴백 | 확정 골격 |

## CB-5-2.2 격리 규약 (확정)

1. ES 는 챗봇 검색·색인 스텝만 의존 — 수집·가공·타 배치는 ES 상태와 무관하게 동작
2. 색인 스텝 실패가 선행 스텝(가공) 커밋을 되돌리지 않는다
3. 검색·검증 실패가 SSE 연결 자체를 깨지 않는다 — 실패 안내 이벤트로 정상 종료

- 검색 단계 실패는 어느 단계(BM25/kNN/RRF/rerank)인지 식별 가능하게
