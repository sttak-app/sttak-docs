# CB-6. 관측성 (챗봇 + 뉴스 AI)

트레이스, 메트릭, 로그의 구성과 Langfuse 연동 방식(OTLP 경로, 본문 기록 정책, 설정 키)은
`../ai-feature/6-observability.md`를 기준으로 한다. 챗봇에서는 **질문 하나가 처리되는 전
과정을 하나의 트레이스로** 확인할 수 있어야 한다. 또한 사용자 화면에 오류로 나타나지 않는
일반 지식 답변 전환과 부족한 근거도 관측 데이터로 확인할 수 있어야 한다.

## CB-6.1 질의 트레이스 구현 방식

- 생성, 재생성, 검수 호출은 비스트림 방식으로 전환하면서(`4-3`) Spring AI의 **자동
  span**을 사용한다. 배치 기능과 같은 구성이므로 별도 연동 작업은 필요하지 않다.
- 이번 개편에서는 **검색 단계(BM25/kNN/RRF/rerank)에만 Micrometer Observation을 직접
  연결한다.** 기존 OTel/OTLP 경로를 사용하므로 새로운 인프라는 필요하지 않다.

질문마다 하나의 트레이스를 만들고 다음 단계별 span을 기록한다.

| span | input / output | 계측 |
| --- | --- | --- |
| query | 사용자 질문과 맥락 `newsId` | 수동 |
| embedding | 질문 임베딩의 모델·토큰 | 자동 |
| bm25 / knn | 각 검색의 히트 청크 ID·스코어 | 수동 |
| rrf | 융합 후 순위 | 수동 |
| rerank | 통과/탈락 청크와 사유 | 자동(LLM) + 수동(결과) |
| generation | 입력 청크 목록, 출력, 토큰 | 자동 |
| rewrite / judge | 피드백 반복을 포함한 재생성·검수 각 호출 | 자동(공용 어댑터 재사용) |
| (전체) | 단계별·총 지연 | 수동 |

**본문 기록 정책**: 운영 환경에서는 배치 기능과 마찬가지로 응답 본문과 청크 본문을
기록하지 않고 메타데이터, 청크 ID, 점수만 남긴다. 다만 **사용자 질문(query)은 운영
환경에서도 기록한다.** 검색 결과가 없거나 근거가 부족한 원인을 분석하고 검색 품질을
개선하려면 질문 내용이 필요하기 때문이다. 사용자 입력에 개인정보가 포함될 수 있으므로
문제가 확인되면 마스킹하거나 기록을 중단하는 방안을 검토한다.

**샘플링**: 처음에는 전체 요청을 기록하도록 1.0으로 설정한다. 챗봇 트레이스는 배치와 달리
사용량에 비례해 늘어나므로 출시 후 실제 트래픽과 비용을 확인한다. 비용이 지나치게 크면
`LANGFUSE_TRACING_SAMPLING` 값을 낮춘다.

## CB-6.2 메트릭 (신설 목록)

| 메트릭 | 태그 | 용도 |
| --- | --- | --- |
| 검색 지연 히스토그램 | `stage`(bm25/knn/rrf/rerank/total) | 지연 예산(NFR2)의 p95 검증과 경보 |
| 결과 없음·근거 부족 카운터 | `mode=zero` / `mode=low`, `stage` | 결과가 없었던 단계와 근거 부족 답변의 발생률을 확인한다. 급증하면 색인과 검색 상태를 점검한다 |
| 검색 인프라 장애 카운터 | — | 일반 지식 답변으로 전환된 검색 장애를 확인하며, 한 건부터 경보 대상으로 검토한다 |
| rerank 탈락률 | — | "확신이 없으면 통과" 원칙(C-FR4)이 지켜지는지 확인한다 |
| **PG↔인덱스 데이터 차이** | — | PG 청크 수와 인덱스 문서 수의 차이를 비교해 겉으로 드러나지 않는 색인 실패를 찾는다 |
| 색인 처리·실패 카운터 | — | 배치 상태 |
| 토큰 카운터 | `job=chat` / `job=chat-rerank` | 기존 `sttak.ai.tokens.*` 체계에 포함해 집계한다 |

뉴스 가공 메트릭(토큰, 시도 소진, refusal, `jobTag`의 `news-summary`/`news-sentiment`)은
`../ai-feature/6`의 구현을 그대로 쓴다.

## CB-6.3 경보 후보 (임계는 팀 확정)

PG와 인덱스의 데이터 차이가 계속되는 경우, 검색 결과 없음 비율이 급증하는 경우, 검색
p95가 예산을 넘는 경우, 관리형 서비스 지표를 포함해 검색 인프라 장애가 발생한 경우를
경보 후보로 둔다. 임계값은 `../ai-feature/6`의 경보 표에 추가해 함께 정한다.
