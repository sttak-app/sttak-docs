# CB-2-1. 사용자 스토리 (챗봇)

> 전체 스토리는 `../2-1-user-story.md`. 챗봇 관련 스토리와 RAG 관점 수용 기준.

## CB-2-1.1 스토리

| ID | 스토리 | RAG 관점 수용 기준 |
| --- | --- | --- |
| U-CB1 (←FR-G1) | 뉴스를 읽다가 **"이게 왜 호재야?"** 를 바로 물어보고 싶다. | NEWS 맥락(newsId)이 오면 해당 기사 청크가 1차 참고로 승격된다. 답변 근거가 그 기사에서 나온다 |
| U-CB2 | **"PER가 뭐야"** 같은 용어 질문에 정확한 풀이를 받고 싶다. | 용어 원천(용어 사전)이 검색 대상에 포함된다 — 뉴스 청크만으로 커버하지 않는다 |
| U-CB3 | **"삼성전자 관련해서 무슨 일 있었어?"** 처럼 내 종목 기준으로 묻고 싶다. | 종목 필터(stock_codes)가 검색에 반영된다 |
| U-CB4 | 기사에서 본 **표현 그대로** 물어도("유상증자 발표했다던데") 그 기사를 찾아주면 좋겠다. | 어휘 검색(BM25)이 원문 제목·스니펫 표현을 매칭한다 — 개편의 핵심 이득 |
| U-CB5 (←U19) | 답변에 **추천성 표현이 없고 출처가 붙기를** 바란다. | 가드레일 적용(방식은 §CB-4-3 결정) + SSE source 이벤트로 출처 반환 |
| U-CB6 | 질문하면 **바로 답이 흐르기 시작**하면 좋겠다. | 첫 토큰 지연 예산 준수 — 검색·rerank·가드레일이 이 예산 안에서 설계된다 (수치는 §CB-2-2) |

## CB-2-1.2 톤·행동 계약

- 존댓말, 학습 보조 톤 — `../ai-feature/2-1` 의 페르소나 계약 공유
- **근거 우선**: 자료에 있으면 자료로, 없으면 그 사실을 정직하게 — 없는 근거를 지어내지 않는다
- 클라이언트가 매 호출 전체 히스토리를 보낸다(apidocs §7) — 서버 세션 저장소 없음 유지

## CB-2-1.3 확장 파킹

| 항목 | MVP | 확장 후보 |
| --- | --- | --- |
| 지식 원천 | 가공 뉴스 + 용어 사전 | 공시(DART)·차트 신호 해설·퀴즈 해설 청크화 |
| 멀티홉 질의 ("미국 금리→반도체 영향") | 1홉 검색 (ADR-016 한계 유지) | 인과 그래프 (3-1 §3-1.12 파킹 그대로) |
| 원문 전문 | 제목+스니펫까지 (저작권 경계) | 적법 경로(제휴·RSS) 확보 시 재론 |
