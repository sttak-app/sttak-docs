# CB-4-4. 평가 계획 (챗봇 + 뉴스 AI)

평가 원칙은 `../ai-feature/4-4`와 같다. 설계는 측정 결과를 근거로 결정하고, 프롬프트와 검색
파라미터는 평가셋으로 확정한다(NFR6). 평가셋은 구현 전에 준비한다. `4-1`부터 `4-3`까지
평가 결과에 따라 정하기로 한 항목도 이 과정에서 확정한다.

## CB-4-4.1 검색 평가셋

평가셋은 질문과 정답 청크의 쌍으로 만들며 다음 유형을 반드시 포함한다.

| 유형 | 예 | 검증하는 것 |
| --- | --- | --- |
| ① 사건 질문 | "삼성전자 무슨 일 있었어?" | 종목 필터 + 의미 검색 |
| ② 종목 영향 질문 | "이거 왜 호재야?" | 판단 내용의 검색 가능성, NEWS 승격 |
| ③ 용어 질문 | "PER이 뭐야?" | 용어 사전의 청크가 검색되는지 |
| ④ 기사 표현 그대로 질문 | "유상증자 발표했다던데?" | 어휘 검색(BM25)을 추가한 효과 |
| ⑤ 정답 없는 질문 | 코퍼스 밖 주제 | 0건·저근거 행동 (C-FR6) |

- **recall@30**으로 정답 청크가 rerank 입력 후보(RRF 상위 30개, `4-2`의 후보 수와 일치)에
  포함된 비율을 측정하고, 검색 실패율(1 − recall@30)도 함께 기록한다. 최종 선택은 rerank가
  담당하므로 MRR처럼 순위에 민감한 지표보다 정답이 후보 안에 포함됐는지가 더 중요하다.
- 라벨링·채점은 평가용 모델이 수행하고 경계 사례만 사람이 검수한다. **피평가 모델과 평가
  모델은 분리**한다.

## CB-4-4.2 실험 축

| 축 | 비교 | 답하는 질문 |
| --- | --- | --- |
| 검색 방식 | 현재 벡터 검색만 사용한 결과와 하이브리드 검색(BM25+벡터+RRF) 결과 비교 | 검색 방식 전환의 근거. 특히 유형 ④에서 차이를 확인한다 |
| 검색 파라미터 | 후보 수, 융합 상수 | `4-2`에서 정하지 않은 값을 확정한다 |
| rerank | 판정 문안과 통과 기준을 조정하고 지연을 측정 | 정상 청크를 지나치게 제외하지 않으면서 정확도를 높이는 문안을 찾는다 |
| 임베딩 모델 | 후보 간 recall 비교 | 비용 차이의 근거 |

모든 조합을 한꺼번에 평가하지 않는다. 검색 방식을 먼저 확정한 다음 나머지 항목을 하나씩
평가해 여러 변경의 효과가 섞이지 않게 한다.

## CB-4-4.3 답변 품질·가드레일 평가

- **답변 평가 기준**: 참고 자료 충실도, 자료에 없는 내용 생성 여부, 출처 정확성, 말투, 자료가
  적을 때의 처리 규칙 준수 여부를 확인한다.
- **위반 유도 평가셋**: 챗봇 프롬프트(`CHAT_SLOT` 포함)를 기준으로 재생성과 검수의 위반
  제거율과 오탐률을 다시 측정한다. 배치 기능의 측정값(`../ai-feature/4-4`)은 배치 프롬프트를
  기준으로 하므로 그대로 적용할 수 없다. 챗봇 전용 후보 패턴(`4-3`)도 이 평가에서 확인된
  유형으로만 작성한다.
- **지연 시간**: 검색만 수행한 경우, rerank까지 수행한 경우, 생성·재생성·검수를 마친 답변이
  도착한 경우로 나누어 시나리오별 p95를 측정하고 NFR2의 지연 예산을 검증한다.

## CB-4-4.4 산출물 규약

- 평가 데이터·스크립트는 저장소 밖에 보관한다(평가 산출물은 커밋하지 않는다).
- 뉴스 요약이나 판단 프롬프트를 바꾸면 `../ai-feature/4-4`의 절차에 따라 다시 검증한다.
  가공된 뉴스가 챗봇의 참고 자료이므로 뉴스 품질이 떨어지면 챗봇 답변 품질도 함께 떨어진다.
