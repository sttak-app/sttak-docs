# CB-4-3. 구현: 답변 생성과 가드레일 (구현 예정)

질의 파이프라인의 후반부(생성 → 재생성 → 검수 → 전송)를 구현하기 위한 계획이다. 검증 파이프라인의
공통 구현은 `../ai-feature/4-1`, 프롬프트 관리 원칙은 `../ai-feature/4-2`를 따른다.

## CB-4-3.1 비스트림 방식으로 전환

- 생성, rerank, 재생성, 검수에는 배치 기능과 같은 **luna 단일 모델**(`gpt-5.6-luna`)을
  사용한다.
- 답변 생성은 **비스트림 호출**로 구현한다. 모든 과정을 통과한 뒤 전송하기 때문에 벤더의
  SSE 델타를 받을 필요가 없다. 이에 따라 배치 기능과 동일한 **Spring AI `ChatModel`**로
  전환하고 자동 트레이스 계측도 적용한다(`6`).
- 기존 스트리밍 어댑터(`OpenAiChatStreamAdapter`: SSE 델타 파싱, 스트리밍 필터, 취소
  리스너)는 새 구현으로 **대체한 뒤 제거한다.** 부분 문자열 방식의 기존
  `ChatGuardrail`(@Deprecated)도 공통 파이프라인으로 전환하면서 제거한다.
- 비스트림 방식에서는 생성 호출에도 배치와 동일한 지수 백오프 재시도 3회를 적용할 수 있다.
  다만 사용자의 대기 시간이 늘 수 있으므로 NFR2의 지연 예산 안에서 운영한다.

## CB-4-3.2 답변 생성 프롬프트 개정 방향

프롬프트 원문은 코드를 단일 출처로 관리한다. 구체적인 문구는 구현 단계에서 평가셋
검증(NFR6)과 함께 정하며, 다음 네 가지 방향을 따른다.

1. **[참고 자료] 사용법 안내**: rerank를 통과한 자료는 0~30개이며, NEWS 승격 청크가 있으면
   별도로 추가될 수 있음을 프롬프트에 설명한다.
2. **근거가 적거나 없는 경우의 동작**(C-FR6): 프롬프트를 조립할 때 최종 참고 자료 수에 따라
   분기한다. **5개 이하이면** "관련 자료가 충분하지 않다"는 안내와 일반 지식 보완 지시를
   추가한다. **0개이면** [참고 자료] 항목 없이 일반 지식으로 답한다. "자료가 없다"고
   단정하거나 사과하는 표현은 쓰지 않는다. 6개 이상이면 일반적인 근거 기반 답변을 만든다.
3. **근거 사용 원칙**: 자료에 없는 내용을 자료에 있는 것처럼 말하지 않는다.
   출처는 코드가 구성하므로 본문에 URL을 쓰지 않는다.
4. **가드레일 지시 제거**: 투자 권유 차단은 2단계 검증 파이프라인에서 담당한다. 생성
   프롬프트에는 답변 품질에 관한 지시만 남긴다.

## CB-4-3.3 모든 검증을 통과한 뒤 전송

```
질문 → 검색 → 생성 → 무조건 재생성 → 검수(+후보 힌트) → (피드백 ≤2회) → 통과 시 전송
                └── 그동안 진행 단계 이벤트: "생성 중" → "다듬는 중" → "검수 중"
```

- 검증 전 텍스트는 사용자에게 전송하지 않아 위반 문구가 노출되지 않게 한다. 즉시성(U-C6)보다
  U-G1 보증을 우선한 결정이다.
- 본문을 조금씩 보내는 대신 진행 단계 이벤트를 전송해 체감 대기 시간을 줄이고, 완성된
  본문은 한 번에 전송한다. 타이핑 효과는 클라이언트에서 선택해 적용할 수 있다. 진행 단계,
  완성 본문, 출처, 종료 이벤트의 계약은 iOS 계약 문서(apidocs)를 기준으로 한다.
- 모든 시도를 소진하면 실패 안내 이벤트를 보낸 뒤 정상 종료한다. 검증하지 않은 답변을
  대신 보내지는 않는다.
- 재생성·검수는 **공용 가드레일 어댑터를 재사용**하고, 챗봇용 형식 슬롯 `CHAT_SLOT`을
  신설한다. 존댓말과 학습을 돕는 말투, [참고 자료]를 바탕으로 쓴 내용의 사실 및 근거 관계,
  답변의 구조와 분량을 유지해야 한다. 결과 형식은 JSON이 아닌 자유 텍스트다.
- 대화체 조언 문구 같은 챗봇 전용 후보 패턴은 미리 만들지 않는다. 실제 사례를 확인하기 전에
  만든 패턴은 정상 문장을 잘못 탐지할 수 있다. 공통 패턴 23개로 시작하고 평가에서 확인된
  유형만 추가한다.

다음 대안도 검토했으나 적용하지 않는다.

1. 진행 표시 없이 한 번에 반환: 응답이 끝날 때까지 빈 화면을 보여 주게 된다.
2. 본문을 먼저 전송하고 나중에 검수: 위반 문장이 잠시 노출될 수 있고 철회 절차도 복잡하다.
3. 생성 전에만 차단: 다른 기능과 달리 챗봇 답변에는 생성 후 검수가 빠지게 된다.

## CB-4-3.4 출처 구성

- 출처 목록은 **실제로 프롬프트에 넣은 문서의 `source_url`**로 코드에서 만든다(`3-2`
  원칙 6). 같은 기사가 중복되지 않도록 기사 단위로 정리하며, 참고 자료가 없으면 빈 목록을
  반환한다.
- 근거가 5개 이하이거나 없는 경우는 로그, 메트릭, 트레이스에 남긴다(`6`). 발생 비율이
  갑자기 높아지면 색인과 검색 상태를 점검한다.
