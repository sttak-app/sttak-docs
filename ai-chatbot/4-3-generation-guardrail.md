# CB-4-3. 구현 설계 — 생성·가드레일 (결정 항목 카탈로그)

## CB-4-3.1 생성 (확정 골격)

- 모델: luna (ADR-032 정합). 프롬프트 = 시스템(톤·근거 우선·가드) + [참고 자료] ≤N청크(원문
  raw_text) + 히스토리 + 질문
- 전송: 현행 `OpenAiChatStreamAdapter`(RestClient SSE) 유지 — Spring AI 스트리밍 전환은
  ADR-034 에서 의도적 제외. 관측은 수동 Observation (§CB-6)
- ❓ 챗 시스템 프롬프트 개정 — RAG 개편에 맞춘 근거 인용·부재 시 행동 지시. 평가셋으로 검증

## CB-4-3.2 가드레일 — 3안 중 택1 (C-FR9, 최우선 결정)

배치 5기능의 2단 파이프라인(무조건 재작성→판정)은 **완성된 응답**을 전제한다. 챗봇은 SSE
스트리밍이라 그대로 이식 불가 — 다음 중 결정:

| 안 | 구조 | 장점 | 단점 |
| --- | --- | --- | --- |
| (a) 스트리밍 포기 | 생성→재작성→판정 완료 후 일괄 반환 | 배치와 동일 보증 — 실측 그대로 유효 | 체감 지연 큼(3호출 직렬), **SSE 계약 변경**(iOS 협의) |
| (b) 스트리밍 + 사후 판정 | 스트림 내보내며 완료 후 판정 → 위반 시 교체/철회 이벤트 | 스트리밍 유지 + LLM 판정 보증 | 위반 문장이 일시 노출, 철회 이벤트 프로토콜 신설(iOS 협의) |
| (c) 스트리밍 + 사전 가드 | 시스템 프롬프트 가드 + RAG 입력 통제 + 스트림 중 룰 후보 탐지(현행 필터 개선판) | 계약 무변경, 지연 0 | 판정 없는 유일한 기능이 됨 — 근거: 정상 1차 생성 834건 위반 0 실측(프롬프트 자체의 안전성) |

- 판단 재료: U19 보증 수준 vs U-CB6(즉시성) vs iOS 협의 비용. (c)를 기본 후보로 두되
  ❓평가(챗봇용 위반 유도 세트)로 위반율을 실측해 (b) 격상 여부 결정 — 이 실험 설계도 §CB-5 몫
- 어느 안이든 룰 엔진(`InvestmentGuardrail.detect`)은 후보 탐지로 재사용 가능. 구
  `ChatGuardrail` 부분 문자열 경로(@Deprecated)는 이 결정과 함께 제거

## CB-4-3.3 0건·저근거 응답 (C-FR7 연동)

- rerank/검색 0건: §CB-3-2.2 결정 반영
- ❓ 저근거(청크는 있으나 관련 약함) 시 행동 — 프롬프트 지시로 "자료가 충분치 않다" 명시
  유도할지. 평가셋에 이 유형 포함

## CB-4-3.4 프롬프트 관리 원칙 (확정)

- 전문은 코드가 단일 출처, 스펙엔 설계 의도만 (`../ai-feature/4-2` 원칙 공유)
- 문안 변경 = 실측 재검증 세트 (C-NFR8)
