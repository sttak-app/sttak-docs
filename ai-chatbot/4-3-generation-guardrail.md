# CB-4-3. 구현 설계 — 생성·가드레일

## CB-4-3.1 생성 (확정 골격)

- 모델: luna (ADR-032 정합). 프롬프트 = 시스템(톤·근거 우선·가드) + [참고 자료] rerank 통과분
  0~20청크(원문 raw_text) + 히스토리 + 질문
- 전송: **비스트림 호출** — 가드레일 방식 확정(§CB-4-3.2 (a′))으로 벤더 SSE delta 가 불필요해져,
  ADR-034 의 챗봇 제외 사유가 해소됨. 배치와 동일하게 Spring AI ChatModel 전환 가능
  (Langfuse 자동 관측 포함, §CB-6). 구 `OpenAiChatStreamAdapter` 는 개편 시 대체
- 챗 시스템 프롬프트 개정 — 방향 4개 확정(9/19), 문안 작성은 구현 단계 + 평가셋 검증(C-NFR8):
  1. **[참고 자료] 읽는 법 안내** — rerank 통과분 0~20개가 기사 요약 청크·종목판단 청크로
     섞여 들어오는 새 형태를 프롬프트가 설명한다
  2. **저근거·0건 행동** (C-FR7) — 통과 청크 ≤5 면 서버가 프롬프트에 저근거 지시를 넣어
     "관련 자료가 충분치 않다"는 언급을 답변에 포함시키고 일반 지식으로 보완하게 한다.
     "자료가 없다"·사과 표현은 금지. 6개 이상이면 통상 근거 답변 지시
  3. **근거 규율** — 자료가 있으면 자료 기반으로, 자료에 없는 것을 자료에 있는 것처럼 말하지
     않는다(출처 날조 방지). 출처는 source 이벤트가 담당 — 본문에 URL 미기재
  4. **가드레일 블록 제거** — 투자권유 금지 지시는 2단 파이프라인이 전담하므로 프롬프트에는
     품질 지시만 남긴다 (SCRUM-88 배치 5기능 정리와 동일 원칙)

## CB-4-3.2 가드레일 — 확정: 전 과정 통과 후 전송 + 진행 단계 표시 (C-FR9)

배치와 **동일한 2단 파이프라인을 그대로** 적용한다 — 전송은 전 과정 통과 후에만:

```
질문 → 검색 → 생성 → 무조건 재작성 → LLM 판정(+후보 힌트) → (피드백 ≤2회) → 통과 시 전송
                └── 그동안 SSE 로 진행 단계 이벤트: "생성 중" → "다듬는 중" → "검수 중"
```

- **보증**: 위반 노출 0 — 검증 전 텍스트는 사용자에게 절대 나가지 않는다(배치와 동일 수준).
  U19 보증을 즉시성(U-CB6)보다 우선한 결정
- **대기 UX**: 본문 델타 대신 진행 단계 이벤트로 "지금 뭘 하는지"를 보여줘 체감 지연을 완화.
  완성 본문은 한 번에 전송(타자 연출은 클라이언트 재량)
- **소진 시**: 저장·전송하지 않고 실패 안내 이벤트 — 검증 안 된 답변을 내보내는 폴백은 없다
- 재작성·판정은 공용 가드레일 어댑터 재사용. **`CHAT_SLOT` 신설 확정 (9/19)** — 파이프라인을
  타는 이상 필수(재작성이 지킬 형식 규격). 규격 골자: 존댓말·학습 톤 유지 / [참고 자료] 기반
  서술의 사실·근거 관계 불변(중화 금지 — 감성 슬롯의 "판정" 원칙과 동류) / 답변 구조·분량
  유지 / 자유 텍스트(JSON 아님). 문안은 구현 단계 작성 + 실측 검증(C-NFR8)
- **챗 특화 후보 패턴(extraPatterns) 만든다 (확정 9/19)** — 챗봇 고유 위험(대화체 조언 화법 등)
  대응. 패턴 문안은 평가(위반 유도 세트)에서 관찰된 유형으로 작성 — 관찰 전 선제 패턴은
  오탐 위험이 있어 공통 23패턴으로 시작 후 추가

**기각한 대안** (기록): (a) 진행 표시 없는 일괄 반환 — 빈 대기 UX / (b) 스트림 후 판정 —
위반 문장 일시 노출 + 철회 프로토콜 복잡 / (c) 사전 가드만 — 유일하게 판정 없는 기능이 됨.
구 `ChatGuardrail` 부분 문자열 경로(@Deprecated)는 본 확정 구현과 함께 제거.

## CB-4-3.3 0건·저근거 응답 (C-FR7 연동)

- 저근거(통과 ≤5)·0건: C-FR7 확정 규칙 — 프롬프트 조립 시 통과 개수로 분기해 저근거 지시 삽입. 0건이면 [참고 자료] 절 없이, source 빈 목록

## CB-4-3.4 프롬프트 관리 원칙 (확정)

- 전문은 코드가 단일 출처, 스펙엔 설계 의도만 (`../ai-feature/4-2` 원칙 공유)
- 문안 변경 = 실측 재검증 세트 (C-NFR8)
