# CB-3-2. AI 호출 계약 (챗봇 + 뉴스 AI)

각 AI 호출이 어떤 값을 받고 무엇을 반환해야 하는지 계약으로 정의한다. iOS와 주고받는
API·SSE 계약은 별도 문서인 `docs/iosapi/apidocs.md`에서 관리한다. 실패했을 때 결과를
통과시킬지 차단할지는 `5-2-error-handling`에서 설명한다.

## CB-3-2.1 계약의 설계 원칙

1. **프롬프트를 작성하기 전에 입출력 계약부터 정한다.** 프롬프트 내용이 바뀌더라도 계약은
   유지되어야 한다.
2. **구조화된 출력은 스키마로 제한한다.** 필드, 타입, enum을 스키마에 명시한다. 구현이 끝난
   기능은 아래 출력 JSON을 계약으로 사용하며, 스키마에 맞지 않는 응답은 실패로 처리한다.
3. **자유 텍스트는 재생성(재작성) 단계에서만 사용한다.** 이 단계는 표현을 다듬는 작업이라
   별도 출력 스키마가 없다. 대신 길이와 문체 등의 형식 규칙을 입력으로 전달하고, 구조화된
   값은 코드 잠금으로 보호한다.
4. **잠금 값은 AI가 바꿀 수 없다.** 아래에서 🔒로 표시한 값은 재생성 전후에 같은지 코드로
   확인하고, 값이 달라지면 해당 결과를 반려한다.
5. **AI 결과는 검증 없이 저장하거나 전송하지 않는다.** 재생성과 검수를 통과한 결과만 뉴스로
   저장하거나 챗봇 답변으로 전송한다.
6. **`document`에는 기사 원문 URL을 끝까지 유지한다.** 검색 결과부터 rerank, 답변 생성
   입력까지 모든 `document`에 원문 URL이 있어야 한다. 이 URL로 최종 답변의 "참고한 기사"
   목록을 만들기 때문에 중간 단계에서 빠지면 출처를 복원할 수 없다.

## CB-3-2.2 뉴스 가공 호출(구현 완료)

입력 예시는 프롬프트에 어떤 내용이 포함되는지 설명하기 위한 것이다. 실제 입력은 텍스트로
조립하므로 예시의 필드명이 전송 형식을 뜻하지 않는다. 출력에는 strict 스키마를 적용하므로
필드명도 계약에 포함된다.

### CB-3-2.2.1 뉴스 요약

입력: 기사 제목 + 스니펫

```json
{
  "title": "삼성전자, HBM 증산 위해 평택 라인 추가 투자",
  "snippet": "삼성전자가 고대역폭 메모리(HBM) 수요 확대에 대응해 평택 캠퍼스에 생산 라인을 증설한다고 밝혔다. 업계는 …"
}
```

출력:

```json
{
  "easyTitle": "삼성전자, HBM 생산 라인을 늘려요",
  "easyOneLiner": "늘어나는 HBM 수요에 대응하기 위해 평택 생산 라인을 증설한다는 소식이에요.",
  "easyDetail": "삼성전자가 평택 캠퍼스의 HBM 생산 라인을 늘리기로 했어요. 늘어나는 HBM 수요에 대응하기 위한 결정이에요. 증설이 끝나면 기존보다 더 많은 HBM을 생산할 수 있어요.",
  "terms": [
    {
      "term": "HBM",
      "definition": "여러 개의 메모리 반도체를 쌓아 데이터 처리 속도를 높인 고대역폭 메모리"
    }
  ]
}
```

### CB-3-2.2.2 뉴스 호재/악재 판단

입력: 기사 제목 + 스니펫 + 종목 목록

```json
{
  "title": "삼성전자, HBM 증산 위해 평택 라인 추가 투자",
  "snippet": "삼성전자가 고대역폭 메모리(HBM) 수요 확대에 대응해 …",
  "stocks": [ { "stockCode": "005930", "stockName": "삼성전자" } ]
}
```

출력:

```json
{
  "perStock": [
    {
      "stockCode": "005930",
      "sentiment": "POSITIVE",
      "reason": "HBM 수요 확대에 맞춘 생산 라인 증설은 공급 능력을 높이는 데 도움이 될 수 있어요.",
      "whyPoints": ["HBM 수요 확대", "평택 생산 라인 증설"]
    }
  ]
}
```

`sentiment`는 `POSITIVE`, `NEGATIVE`, `NEUTRAL` 중 하나다. `stockCode`와 `sentiment`는
재생성 과정에서 바뀌지 않도록 코드로 잠근다.

## CB-3-2.3 챗봇 질의 호출

입출력 계약은 아래와 같으며, 세부 스키마는 구현할 때 확정한다.

| 호출 | 입력 | 출력 |
| --- | --- | --- |
| 질문 임베딩 | 질문 텍스트 | 벡터 (청크 임베딩과 동일 모델·동일 차원) |
| rerank(관련성 필터) | query + 후보 document 목록 + 판정 프롬프트 | 관련성 판정을 통과한 document 목록(0개~전체) |
| 답변 생성 | 시스템 프롬프트 + [참고 자료 = 남은 document] + 대화 히스토리 + query | 답변 텍스트 (자유 텍스트) |
| 답변 생성(0건 경로) | 검색 결과와 NEWS 승격 청크가 없는 경우: 시스템 프롬프트 + 대화 히스토리 + query | 일반 지식으로 생성한 답변 텍스트(출처 없음) |

- rerank는 순서를 바꾸지 않고 각 문서의 통과 여부만 판단한다. 입력에 없던 `document`가
  출력에 추가될 수 없다.
- 출처(`source`)는 AI가 생성하지 않는다. 입력한 `document`에 포함된 기사 원문 URL을 사용해
  코드에서 구성한다(원칙 6). 최종 답변에는 참고한 기사 목록을 함께 보낸다.

## CB-3-2.4 공통 검증 호출(구현 완료)

**③ 재생성(무조건 재작성)**

- 입력: 1차 생성물 + 형식 규칙 + 검수 피드백(있는 경우)
- 출력: 자유 형식의 재작성문(원칙 3)

**④ 검수(판정)**

입력: 재작성문 + 후보 탐지 힌트

```json
{
  "content": "실적 개선 기대가 커진 지금이 기회예요. …",
  "candidateHints": [ "지금이 기회예요" ]
}
```

출력:

```json
{
  "pass": false,
  "violations": [
    {
      "category": 4,
      "quote": "지금이 기회예요"
    }
  ]
}
```

`category`에는 위반 범주 번호가 들어간다.

## CB-3-2.5 코드 잠금 값

| 대상 | 잠금 값 | 바뀌면 |
| --- | --- | --- |
| 뉴스 판단 | `perStock` 각 항목의 `stockCode` + `sentiment` | 해당 기사 반려. 표현을 다듬는 과정에서 판정이 바뀌면 데이터가 오염될 수 있음 |
| 뉴스 요약 | 구조화 값 없음(텍스트 필드 4개) | 형식 규칙과 검수만 적용 |
