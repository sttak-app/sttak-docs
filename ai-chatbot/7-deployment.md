# CB-7. 배포 (챗봇 + 뉴스 AI)

전체 배포 절차와 인프라 구성은 `../7-deployment.md`를 따른다. 챗봇 개편으로 상시 운영하는
검색 인프라가 처음 추가되므로 프로비저닝, 비용, 전환 절차를 중심으로 설명한다. 실제 인프라
작업은 infra 저장소에서 진행한다. 뉴스 가공 설정과 키는 `../ai-feature/7`과 같은 체계인
`sttak.openai.*`, `OPENAI_API_KEY`를 사용한다.

## CB-7.1 검색 인프라 선택

| 후보 | 판단 |
| --- | --- |
| **AWS OpenSearch Service(관리형)** | 채택 예정. 패치, 복구, 스냅샷을 자동화할 수 있고 **nori가 내장**되어 있으며 VPC/IAM과 연동할 수 있다. RRF는 직접 구현한다(`4-2`) |
| 자체 운영(EC2/ECS) | 채택하지 않음. JVM, 디스크, 스냅샷을 팀에서 직접 운영해야 한다 |
| 외부 SaaS(Elastic Cloud) | 채택하지 않음. AWS 외부 통신 경로와 별도 과금 체계를 관리해야 한다 |

## CB-7.2 환경 구성

- **dev**: 평가와 듀얼런 개발에 사용할 최소 노드 1개(t3.small.search급)를 먼저 구성한다.
- **prod**: 검색이 사용자 요청 처리에 직접 연결되므로 가용성을 우선해 **멀티 AZ 2노드**로
  구성하고 월 비용 증가를 수용한다. 단일 노드에서 장애 시 다시 색인하는 방식은 장애가
  이어지는 동안 챗봇 품질이 계속 낮아지므로 사용하지 않는다.
- 네트워크: VPC와 보안 그룹을 사용해 api/batch 태스크만 접근하게 한다. 자격증명은 시크릿
  저장소에서 관리한다(NFR8).
- 스냅샷: 관리형 자동 스냅샷을 사용한다. 기본 복구 방법은 PG 데이터 전체를 다시 색인하는
  것이다(NFR4).

## CB-7.3 설정·시크릿 카탈로그

| 키 | 용도 |
| --- | --- |
| `OPENSEARCH_ENDPOINT` | 도메인 엔드포인트. 시크릿 또는 환경 변수로 관리한다 |
| `OPENSEARCH_USERNAME`/`PASSWORD` 또는 IAM | 검색 인프라 자격증명. 시크릿 저장소에서 관리한다 |
| `sttak.rag.store` | `pgvector` \| `es`. 듀얼런 중 검색 경로를 선택하며, 전환이 끝나면 기존 경로와 함께 제거한다 |
| 인덱스 alias 이름 | 기본값은 상수로 두고 테스트나 재색인이 필요할 때만 환경 변수로 덮어쓴다 |

프로파일 간 설정 블록 동일 유지 규약은 그대로 적용한다(`../ai-feature/7`).

## CB-7.4 롤아웃 순서

1. dev 도메인을 구성하고 nori 토큰화 표본을 검증한다. 사용자 사전과 동의어 사전은 문제가
   확인될 때만 도입한다.
2. PG 청크 테이블을 마이그레이션하고 기존 임베딩 배치를 확장해 색인 파이프라인을 구성한다(`4-1`).
3. 기존 지식 전체를 한 차례 임베딩하고 색인한다. 일회성 비용은 미리 산정한다.
4. 검색 어댑터를 구현하고 평가(`4-4`)를 거쳐 검색 파라미터와 rerank 문구를 확정한다.
5. 양쪽 색인을 유지한 상태에서 dev의 `sttak.rag.store`를 `es`로 바꾼다. PG와 인덱스의
   데이터 차이, 지연 시간, 검색 결과 없음 비율을 관찰한다(`6`).
6. prod 도메인을 구성하고 듀얼런과 검색 경로 전환을 진행한다. 안정화가 끝나면 기존 검색
   경로와 설정을 제거하고 기존 `knowledge_chunk` 테이블을 DROP한다.

**롤백**: 기존 경로를 제거하기 전에는 어느 단계에서든 `sttak.rag.store=pgvector`로
되돌릴 수 있다. 재배포하지 않고 설정만 바꾸면 된다.

## CB-7.5 비용 항목 (견적 후 팀 공유)

- 검색 도메인의 월 고정비(dev와 prod 멀티 AZ)
- 전체 데이터를 임베딩하는 일회성 백필 비용
- 사용자 요청마다 한 번 실행하는 rerank LLM 호출 비용
- 듀얼런 기간의 이중 저장 비용. 데이터 규모가 작아 영향은 크지 않다.
