# CB-4-2. 구현 설계 — 검색 (결정 항목 카탈로그)

## CB-4-2.1 검색 흐름 (확정 골격)

```
질문 → 질문 임베딩(EmbeddingPort)
     → ① BM25 (search_text, nori, k=20) ┐  둘 다 공통 필터: stock_codes / published_at ≥ now-7d (C-FR1b)
     → ② kNN (embedding, cosine, k=20) ┴→ ③ RRF(k=60) 융합 상위 20 → ④ rerank(관련성 필터) → 통과분 0~20 프롬프트 투입
```

## CB-4-2.2 정할 것

| 항목 | 후보/기본값 | 결정 방법 |
| --- | --- | --- |
| 각 검색 후보 수 | **BM25 20 · kNN 20 확정 (9/19)** — 7일 코퍼스(~2~3천 청크)에서 리콜 충분, 문헌 top-20 실측 | 확정 |
| RRF 상수 | **k=60 (관례) 확정** — 직접 구현(수식 몇 줄). 코퍼스 규모상 튜닝 실익 낮음. 저장소가 OpenSearch 2.19+면 네이티브 하이브리드도 옵션 | 확정 (9/19) |
| 프롬프트 투입 수 | **rerank 통과분 그대로 (0~20, 확정 9/19)** — 별도 캡 없음. rerank 가 RRF 상위 20을 목록형 1호출로 판정, 관련한 것만(0~전부) 통과. 최악 20청크 ≈ 수천 토큰으로 프롬프트 예산 내 | 확정 |
| 후보 선정 방식 | **상위 20개까지 뽑고, 최종은 rerank 가 0~20으로 남긴다 (확정 9/19)** — 점수 임계값(threshold) 컷은 안 씀: 코퍼스가 작아 스코어 분포가 쿼리마다 흔들려 기준이 안 섬. "몇 개 남을지"는 rerank 의 관련성 판정이 정한다 | 확정 (노션 고민 4의 답) |
| kNN 필터 = pre-filter | 필터(종목·7일)에 맞는 청크들 **안에서** 최근접 20개를 뽑는다 — 필터를 나중에 걸면(post-filter) 20개가 전부 걸러져 0개가 되는 리콜 구멍이 생김. ES/OpenSearch kNN 쿼리의 `filter` 파라미터가 pre-filter 로 동작 | 저장소 확정 시 해당 버전 스펙 확인만 |
| 기간 필터 | **최근 7일 고정** (C-FR1b — TERM·NEWS 승격은 예외). 검색 시점 필터, 색인은 전체 보존 | 확정 |
| 용어 검색 결합 | **같은 인덱스에 통합 (확정 9/19)** — 용어를 `source_type=TERM` 문서로 뉴스 청크와 한 인덱스에 색인, 하이브리드 검색 한 번에 함께 걸린다. TERM 은 기간 필터 예외(C-FR1b)·컨텍스트 생성 제외. 별도 질의·결합 로직 불요 | 확정 |
| NEWS 맥락 승격 | newsId 청크를 검색과 무관하게 1차 참고로 (현행 유지) | 확정 |
| 중복 제거 | **확정 (9/19)**: 같은 기사의 요약·판단 청크가 동시에 걸리면 **프롬프트에는 각자 청크로** 넣는다(rerank 가 청크 단위로 판정하는 구조와 정합). **출처(`source` 이벤트)만 기사 단위 dedup** — 같은 기사가 출처 목록에 두 번 나오지 않게 | 확정 |

## CB-4-2.3 rerank — 채택 확정 (C-FR8, 9/19), 문안·기준은 평가로

노션 안: RRF 결과를 LLM 이 query 관련성으로 판정해 **관련 있는 것만 남긴다** — 상위 N개
컷이 아니라 통과 개수가 가변(0~전부)인 게이트다. 그래서 0건 폴백(C-FR7)과 직결된다. 검토 관점:

| 관점 | 내용 |
| --- | --- |
| 이득 | 정밀도 — 관련 없는 청크가 프롬프트에 끼는 것 차단 |
| 지연 | 사용자 질의마다 LLM +1호출이 생성 **앞에 직렬** — 첫 토큰 지연 직격 (C-NFR1 예산 안인지 실측) |
| 비용 | 쿼리당 +1호출 (배치가 아니라 사용자 트래픽 비례) |
| 과필터 위험 | 다 걸러서 0건 → 일반 개념 답변으로 빠짐(C-FR7) — 틀린 답은 아니나 근거 있는 답변 기회를 잃음. **"확신 없으면 통과"** 원칙 필수 |

채택은 확정 — 평가는 채택 여부가 아니라 **프롬프트 문안·통과 기준·지연 영향(C-NFR1 예산 내)**
검증용이다. 확정 원칙: "확신 없으면 통과"(과필터 금지), 판정 불능은 전체 통과(fail-open —
가드레일 판정과 동일 축). 문안·기준 확정 시 본 절에 기록.

## CB-4-2.4 검색 품질 레버 (우선순위)

1. Contextual Retrieval 합본 색인 (확정) — 문헌 실측 실패율 49% 개선의 주 레버
2. nori 사용자·동의어 사전 (고려 사항 — 기본 설정으로 시작, 토큰화 검증에서 문제 시 도입)
3. 원문 제목·스니펫 검색 필드 포함 (확정)
4. rerank (채택 확정 — 문안·기준은 평가로)
