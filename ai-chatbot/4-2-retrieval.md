# CB-4-2. 구현 설계 — 검색 (결정 항목 카탈로그)

## CB-4-2.1 검색 흐름 (확정 골격)

```
질문 → 질문 임베딩(EmbeddingPort)
     → ① BM25 (search_text, nori)  ┐  둘 다 공통 필터: stock_codes / published_at ≥ now-7d (C-FR1b)
     → ② kNN (embedding, cosine)   ┴→ ③ RRF 융합 → ④ (rerank? 관련성 필터, 개수 가변) → 상한 N 적용 → 프롬프트 투입
```

## CB-4-2.2 정할 것

| 항목 | 후보/기본값 | 결정 방법 |
| --- | --- | --- |
| ❓ 각 검색의 후보 수 k | BM25 k=?, kNN k=? (예: 각 20) | 평가셋 튜닝 |
| ❓ RRF 상수 | 관례 k=60, 직접 구현(수식 몇 줄) | 기본값으로 시작, 평가로 조정. 저장소가 OpenSearch 2.19+면 네이티브 하이브리드도 옵션 |
| ❓ 최종 top-N (프롬프트 투입) | 현행 8 | 평가셋 — Contextual Retrieval 문헌은 top-20 유리라 하나 프롬프트 길이·지연과 트레이드오프 |
| ❓ **top-k vs score threshold** | **top-k 고정 권장** — 코퍼스가 작아 스코어 분포가 쿼리마다 흔들려 threshold 단독은 위험. 거르기는 rerank/생성 단계 몫 | 평가셋 (노션 고민 4의 답) |
| ❓ kNN 필터 방식 | pre-filter (필터 먼저 → kNN) 확인 | 저장소 스펙 확인 |
| 기간 필터 | **최근 7일 고정** (C-FR1b — TERM·NEWS 승격은 예외). 검색 시점 필터, 색인은 전체 보존 | 확정 |
| ❓ 용어 검색 결합 | (a) 같은 인덱스 source=TERM 문서로 통합 검색 (b) term 전용 인덱스 별도 질의 후 결합 (현행 k=3 상당) | 설계 결정 |
| NEWS 맥락 승격 | newsId 청크를 검색과 무관하게 1차 참고로 (현행 유지) | 확정 |
| 중복 제거 | (원천 타입, 원천 ID) 기준 — 같은 기사의 요약·판단 청크 동시 히트 시 묶음 규칙 ❓ | 청크 분할안 확정 후 |

## CB-4-2.3 rerank — 채택 자체가 결정 (C-FR8)

노션 안: RRF 결과를 LLM 이 query 관련성으로 판정해 **관련 있는 것만 남긴다** — 상위 N개
컷이 아니라 통과 개수가 가변(0~전부)인 게이트다. 그래서 0건 폴백(C-FR7)과 직결된다. 검토 관점:

| 관점 | 내용 |
| --- | --- |
| 이득 | 정밀도 — 관련 없는 청크가 프롬프트에 끼는 것 차단 |
| 지연 | 사용자 질의마다 LLM +1호출이 생성 **앞에 직렬** — 첫 토큰 지연 직격 (C-NFR1 예산 안인지 실측) |
| 비용 | 쿼리당 +1호출 (배치가 아니라 사용자 트래픽 비례) |
| 과필터 위험 | 다 걸러서 0건 → C-FR7 폴백 남발. **"확신 없으면 통과"** 원칙 필수 (가드레일 판정 실측 원칙 준용) |

❓ 결정 방법: 평가셋 A/B (rerank 유/무 × 품질/지연) — 무로 시작해 품질 미달 시 켜는 단계적
도입도 유효. 채택 시 프롬프트·통과 기준·판정 불능 처리(통과)를 본 절에 확정 기록.

## CB-4-2.4 검색 품질 레버 (우선순위)

1. Contextual Retrieval 합본 색인 (확정) — 문헌 실측 실패율 49% 개선의 주 레버
2. nori 사용자 사전·동의어 (검증 선행)
3. 원문 제목·스니펫 검색 필드 포함 (확정)
4. (평가 후) rerank
