# AF-4-4. 평가 방법과 결과

평가 데이터와 스크립트는 저장소 밖에서 관리하며 평가 결과물은 커밋하지 않는다. 이 문서에는
평가 방법과 결론만 기록한다.

## AF-4-4.1 평가 원칙

1. **설계는 측정 결과로 결정한다.** 파이프라인 구조, 검증 방식, 프롬프트의 세부 문구까지
   데이터를 근거로 정한다. 예상만으로 프롬프트를 바꾸지 않는다.
2. **사람의 판정을 정답으로 사용한다.** 경계 문장과 오탐 여부의 최종 라벨은 사람이 정한다.
3. **정상 데이터와 위반 유도 데이터를 나눠 평가한다.** 정상 문장을 보호하는 능력과 위반
   문장을 차단하는 능력은 별도의 실험으로 측정한다.
4. **결과가 반복되는지도 확인한다.** LLM 판정은 달라질 수 있으므로 같은 입력을 여러 번
   평가해 결과가 얼마나 흔들리는지 측정한다.
5. **프롬프트 문구를 검증 자산으로 관리한다.** 문구가 바뀌면 기존 평가 결과는 더 이상
   유효하지 않으므로 변경 전에 다시 검증한다.
6. **피평가 모델과 평가 모델은 분리한다.**

## AF-4-4.2 실험 방법과 결과

| 실험 | 설계 | 결론 |
| --- | --- | --- |
| 단어 필터 오탐 측정 | 금지어 목록을 정상 결과물 834건에 적용 | 68건을 잘못 차단했으며 모두 교육 문장이나 부정 문맥이었다. 이를 근거로 부분 문자열 방식을 폐기했다 |
| 후보 탐지 정규식 개선 | 문장 끝의 권유 표현과 네 가지 예외 규칙을 적용한 뒤 기존 오탐 사례로 회귀 검증 | 같은 834건에서 오탐 없이 합성한 위반 문장을 모두 찾았다. 이 결과를 근거로 검수 힌트에 사용한다 |
| 재생성 방식 비교 | 정상 데이터 150건과 위반 유도 데이터 50건으로 항상 재생성하는 방식과 조건부 방식을 비교 | 두 방식의 위반 제거율은 같았지만 항상 재생성한 방식에서만 문체 개선 효과가 있어 이 방식을 선택했다 |
| 재생성 안전성 | 원문과 결과를 동일·개선·동등·악화로 모두 분류하고 라벨 보존 여부 확인 | 5건이 개선되고 2건이 악화됐다. 악화 사례는 프롬프트 두 줄을 보완해 막았으며 라벨과 정답이 바뀐 사례는 없었다 |
| "그대로 출력" 규칙 제거 | 해당 규칙을 뺀 프롬프트로 150건을 다시 실행하고 차이를 모두 검토 | 개선 건수가 악화 건수보다 많거나 같은 결과를 유지해 규칙을 제거했다 |
| 검수 방식 비교 | 정상 문장 250건과 경계 문장 22건을 사람이 판정한 뒤 규칙 기반 방식과 LLM을 반복 평가 | 두 방식 모두 오탐은 없었다. 경계 문장 정확도는 규칙 기반 방식이 50%, LLM이 86%였으며 반복 판정도 바뀌지 않아 LLM을 최종 검수 방식으로 선택했다 |
| 위반 유도 | 위반 표현이 나오도록 프롬프트를 구성한 뒤 전체 파이프라인의 제거율 측정 | 검사 대상 위반을 모두 제거했다. 절반 이상은 1차 생성 단계에서 이미 중립적인 표현으로 바뀌었다 |
| 주입 방어(회고) | `rationale`에 지시문 24건 삽입 | 프롬프트 주입에 성공한 사례가 없어 입력 취급 규칙이 효과가 있음을 확인했다 |

## AF-4-4.3 재검증 절차 (프롬프트 변경 시)

1. 보관 중인 평가셋을 다시 사용한다. 검수용 정상·경계 문장, 재생성 대상, 위반 유도 데이터가
   모두 포함되어야 한다.
2. 합격 기준은 **오탐 0건 유지, 경계 문장 정확도 기존 이상, 개선 건수 ≥ 악화 건수,
   라벨·정답 변경 0건**이다.
3. 결과를 평가 기록에 추가하고, 프롬프트 변경의 근거를 남긴다.
