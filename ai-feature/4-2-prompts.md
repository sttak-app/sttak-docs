# AF-4-2. 구현: 프롬프트 세트

프롬프트 전문은 코드에서만 관리한다. 가드레일 프롬프트는 `GuardrailPrompts`, 기능별 생성
프롬프트는 각 `<기능>Support` 클래스에 있다. 이 문서에는 설계 기준과 평가 결과만 기록한다.
모든 프롬프트 문안은 평가를 마친 자산이므로, 수정한 뒤에는 정상 문장 250건과 경계 문장
22건으로 검수를 다시 평가하고 재생성 데이터 150건도 다시 확인해야 한다(NFR3). 프롬프트를
합치거나 나누는 작업도 변경에 포함한다. 검증하지 않은 병합본을 운영에 적용했다가 되돌린
사례가 있기 때문이다.

## AF-4-2.1 프롬프트 목록과 평가 결과

| 프롬프트 | 위치 | 검증 실적 |
| --- | --- | --- |
| 재생성 코어 (11범주 + 수정 원칙) | `GuardrailPrompts.REWRITE_SYSTEM_CORE` | 150건 향상 5 : 회귀 2, 라벨 깨짐 0 |
| 검수 기준 (11범주 + 비위반 5유형) | `GuardrailPrompts.JUDGE_SYSTEM` | 오탐 0/250, 경계문 86%, 반복 뒤집힘 0 |
| 형식 슬롯 5종 | `GuardrailPrompts.*_SLOT` | 판정 근거 훼손 보강 전 4건 → 후 0건 |
| 퀴즈 생성 | `QuizGenerationSupport.SYSTEM_PROMPT` | 2차 평가 합격 |
| 차트 해설 생성 (350자 확장판) | `ChartSignalExplanationSupport.SYSTEM_PROMPT` | 96건×2회 실행 전 축 4.9+, 파라미터 날조 0 |
| 회고 생성 | `TradeRetrospectiveSupport.SYSTEM_PROMPT` | 2차 평가 합격, 주입 방어 0/24 |

뉴스 요약과 판단 프롬프트는 `NewsAnalysisSupport`에 있으며 `../ai-chatbot/4-1`에서 설명한다.

## AF-4-2.2 재생성 프롬프트의 공통 내용

```
당신은 투자 학습 서비스의 콘텐츠 검수자다. 아래 글에서 다음에 해당하는 표현만
중립적인 학습 표현으로 바꿔 다시 써라:
1. 매수/매도 권유 … 11. 특정 종목의 비교 우위 단정

[수정 원칙]
- 위 11가지 외에 "이 글의 형식"에 명시된 문체 규격도 교정할 수 있다.
  그 밖의 내용·수치·회사명·날짜·판정은 바꾸지 않는다.
- 표현을 지우는 게 아니라 학습 톤으로 바꾼다 — "지금이 저점이에요" →
  "저점 부근으로 해석하는 시각도 있어요"처럼 정보는 남기고 권유만 뺀다.
- 금지 표현을 설명·경계하는 문장은 위반이 아니다 — 그대로 둔다.
- 제3자의 발언·평가·전망을 전달하는 문장은 사실 보도이므로 수정 대상이 아니다.
- 용어 풀이(괄호 설명 포함)는 삭제하지 않는다.
```

- 마지막 두 항목은 평가에서 발견한 문제 두 가지, 즉 인용문의 의미를 바꾸는 문제와 용어
  풀이를 삭제하는 문제를 막기 위해 추가했다.
- "고칠 것이 없으면 그대로 출력"이라는 지시는 넣지 않는다. 해당 지시를 제거하고 150건을
  다시 실행했을 때도 개선된 결과가 나빠진 결과보다 많거나 같았다.
- `rewriteSystem(formatSlot)`은 공통 내용과 기능별 출력 형식을 합쳐 시스템 프롬프트를 만든다.

## AF-4-2.3 검수 기준

```
[위반이 아닌 것 — 반드시 통과시켜라]
- 부정·경계 문맥 / 교육적 언급 / 인용·명사화(퀴즈 오답 선지 포함) / 사실 전달 / 확률적 해석

판단 원칙: 글쓴이가 독자에게 직접 매매 행동·기대를 유도하는가? 그렇지 않으면 통과다.
확신이 없으면 통과(pass=true)로 판정한다 — 의심만으로 실패시키지 않는다.
```

- 위반으로 보지 않을 다섯 가지 유형은 단어 필터 평가에서 실제로 잘못 차단한 사례를 바탕으로
  정했다.
- 출력은 strict `json_schema`인 `{pass, violations[{category(1..11), quote}]}`를 따른다.
  `category`와 `quote`는 다음 재생성의 피드백으로 사용한다(`3-2` 검수 계약).

## AF-4-2.4 기능별 출력 형식

| 슬롯 | 지키는 것 | 핵심 문구 |
| --- | --- | --- |
| `QUIZ_SLOT` | 선지 의미·정답 번호 절대 불변 | "오답 선지 안의 위반성 표현은 개념 시험 목적이면 유지할 수 있다" |
| `CHART_SLOT` | 존댓말, 4~5문장, 350자, 가능성을 나타내는 표현 | "'~로 해석되곤 해요' 같은 표현을 유지한다" |
| `RETRO_SLOT` | 존댓말, 총평 40자, 항목 개수 | "아쉬운 점의 질문형과 학습 주제 부착을 유지한다" |

`SUMMARY_SLOT`과 `SENTIMENT_SLOT`은 뉴스 기능에서 사용한다. 특히 판단 결과의 방향을
설명하는 문장은 예측이 아니라 판정 근거이므로 중립적인 표현으로 바꾸지 않는다는 규칙이
중요하다. 이 규칙을 추가하기 전에는 판정 근거의 의미가 달라진 사례가 4건 있었지만, 추가한
뒤에는 없었다.

## AF-4-2.5 생성 프롬프트의 공통 원칙

1. **가드레일 지시는 넣지 않는다.** 생성 프롬프트에는 품질에 관한 지시만 넣고, 투자 권유
   표현 차단은 검증 파이프라인이 담당한다. 1차 생성 결과 834건에서 위반이 없었던 평가
   결과를 근거로 역할을 분리했다.
2. **입력에 없는 내용을 만들지 않는다.** 차트 해설에는 고정 설명문과 함께 입력으로 받은
   수치만 사용하도록 지시한다. 회고에서는 전달받은 손익만 사용하고 새로 계산하거나 추정하지
   않도록 한다.
3. **억지로 내용을 채우지 않는다.** 회고할 만한 장점이 없다면 잘한 점을 만들어 내지 않도록
   지시한다. 기능마다 모델이 내용을 억지로 채우기 쉬운 방향을 확인해 막는다.
4. **프롬프트 주입을 방어한다.** 사용자가 작성한 글이 들어가는 회고 기능에만 적용한다. 매매
   근거 안에 지시나 요청이 있어도 따르거나 출력에 옮기지 않으며, 해당 지시를 언급하거나
   거절하는 문장도 출력하지 않도록 명시한다.
5. **출력은 스키마로 제한한다.** OpenAI Structured Outputs의 strict `json_schema`를
   사용한다. 회고의 `evaluations.type`은 `GOOD`, `BAD`, `IMPROVEMENT` 중 하나만 허용한다.
