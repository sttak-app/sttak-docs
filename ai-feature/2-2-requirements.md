# AI-2-2. 요구사항 (AI 기능)

> 전체 요구사항은 `../2-2-requirements.md` (FR-G3, CON-S5, NFR-S1 등은 그쪽이 원본).
> 여기서는 AI 기능 5종에 특화된 요구사항을 AI-FR / AI-NFR 로 정리한다.

## AI-2-2.1 기능 요구사항 (AI-FR)

| ID | 요구사항 | 근거 |
| --- | --- | --- |
| **AI-FR1** | **뉴스 요약**: 기사 1건을 easyTitle(25자 안팎)·easyOneLiner(40~60자)·easyDetail(3~5문장)·terms(1~3개)로 재구성한다. 원문 문장 복사 금지, 기사에 없는 사실 추가 금지. | ADR-003, 요약 v2 |
| **AI-FR2** | **뉴스 호재/악재 판단**: 종목별 perStock(sentiment/reason/whyPoints). 기사에 담긴 사실만 근거, 방향이 읽히면 영향이 작아도 POSITIVE/NEGATIVE, 방향을 세울 수 없을 때만 NEUTRAL. 투자심리 단독 근거 금지. | 판정 v4 |
| **AI-FR2b** | 요약과 판단은 **독립 트랙**으로 처리한다 — 각자 검증된 단독 프롬프트(v2/v4)로 생성→재작성→판정을 따로 거친 뒤 병합. 입력(기사)·출력(NewsAnalysis)·저장은 단일이며, 실패는 기사 단위(한 트랙 실패 = 기사째 재시도, 부분 성공 없음). 두 출력의 교차 모순은 스모크 실측 0/100. | 검증-운영 정합, PR #53 |
| **AI-FR3** | 퀴즈는 개념/정의/원리만 다루는 4지선다 + 2~3문장 해설. 정답 유일성·오답 그럴듯함·선지 길이 균형. 기존 문항과 임베딩 유사도 ≥ 0.80 이면 폐기 후 재생성(문항당 최대 3회). | ADR-019 |
| **AI-FR4** | 차트 신호 해설은 신호당 1건·불변, ①의미 ②발생 원리 ③이번 발생 맥락 ④균형 감각 구성. 감지 파라미터는 고정 설명문으로 주입(모델이 지어내지 못하게). subsequent_direction 은 입력에 넣지 않는다. | ADR-025 |
| **AI-FR5** | 매매 회고는 매도 정산 후 생성. 핵심 평가 대상은 rationale. 잘한 점 날조 금지, 아쉬운 점은 점검 질문 + 학습 주제. evaluations 는 rationale 자체 평가 1~3개(GOOD/BAD/IMPROVEMENT). | ADR-024 |
| **AI-FR6** | 모든 생성물은 저장 전 **2단 가드레일 파이프라인**을 통과한다: 무조건 재작성 → LLM 판정(룰 엔진 후보 힌트) → 실패 시 피드백 재작성 최대 2회 → 통과 시 저장 / 소진 시 폴백. | ADR-032 |
| **AI-FR7** | 가드레일 위반은 11범주로 정의한다: 매수/매도 권유 · 시세 예측 단정 · 수익 보장 · 매매 유인 · 목표가 제시 · 배수 약속 · 레버리지/집중투자 권유 · 손실 만회 조언 · 조급함 조장 · 루머 암시 · 종목 비교 우위 단정. | GuardrailPrompts |
| **AI-FR8** | 다음은 위반이 **아니다** (오탐 금지): 부정·경계 문맥, 교육적 언급, 인용·명사화(퀴즈 오답 선지 포함), 제3자 발언·기사 내용의 사실 보도, 확률적 해석. 확신이 없으면 통과. | 실측 오탐 5유형 |
| **AI-FR9** | 재작성이 건드리면 안 되는 구조화 값은 코드로 잠근다: 뉴스 perStock 의 stockCode+sentiment, 퀴즈 correctChoice, 회고 evaluations 개수+type 시퀀스. 불일치 시 해당 건 생성 실패로 반려. | ADR-032 §4 |
| **AI-FR10** | 생성 실패·파이프라인 소진은 해당 건만 실패시키고 배치·수집·정산은 계속된다. 실패 건은 다음 배치가 "결과가 아직 없는 대상만 골라내는 조회"(anti-join)로 자연히 다시 집어간다(멱등 재생성). | ADR-024/025 흡수 정책 |

## AI-2-2.2 비기능 요구사항 (AI-NFR)

| ID | 요구사항 | 비고 |
| --- | --- | --- |
| **AI-NFR1** | 조회 경로 LLM 호출 0회 — 생성은 전부 배치, api 는 저장된 결과만 읽는다. | 두 갈래 구조 |
| **AI-NFR2** | 생성 모델은 luna(`gpt-5.6-luna`) 단일. 모델·프리픽스는 설정으로 오버라이드 가능(`OPENAI_MODEL`). 벤더 재분기는 ADR 필요. | ADR-032 |
| **AI-NFR3** | API 키는 환경변수(`OPENAI_API_KEY`)로만 주입. 로그·커밋·예외 메시지 노출 금지. | NFR-S1/CON-S1 |
| **AI-NFR4** | 토큰 사용량을 `sttak.ai.tokens.{input,output}{provider,job}` 카운터로 발행한다. job 태그로 기능·가드레일 단계(guardrail-rewrite/judge)를 구분한다. | NFR-O3 |
| **AI-NFR5** | 파이프라인 비용은 **트랙당** LLM 3호출(생성+재작성+판정)을 상한 기준으로 수용한다 — 뉴스는 기사당 2트랙 6호출, 나머지는 건당 3호출. | ADR-032 |
| **AI-NFR6** | 회당 생성량은 batch-size 로 상한: 차트 100 · 회고 50 · 퀴즈 10 · 뉴스 chunk 10/page 50. 백필은 env 상향으로 1회 처리. | 비용·부하 격리 |
| **AI-NFR7** | 프롬프트 문구는 검증된 자산이다 — 재작성·판정 프롬프트 수정 시 실측 세트(판정 250+22건, 재작성 150건) 재검증을 요구한다. | GuardrailPrompts 주석 |
| **AI-NFR8** | 사용자 유래 입력(rationale)은 프롬프트 주입 방어를 거친다: 개행 제거 + "내부 지시 무시·미인용" 지시. 판정 refusal 은 통과가 아닌 반려. | ADR-024 §5, ADR-032 §3 |
| **AI-NFR9** | 벤더 호출 규격은 `3-2 §AI-3-2.0` 표로 고정한다("요청 바이트 고정" — strict 손 스키마·temperature 미전송·ADR-014 재시도). 이탈하는 변경은 실측 재검증 사안이며, 어댑터마다 회귀 가드 테스트를 둔다(§AI-5-1.3a). | ADR-033/034 |

## AI-2-2.3 명시적 아웃 오브 스코프

- 챗봇 (RAG 재설계 후 `ai-chatbot/` 에서 정의, 가드레일 파이프라인 합류도 그때)
- 뉴스 원문 전문 크롤링 (저작권·약관 리스크 — 입력은 Naver 제목+요약 스니펫으로 한정)
- 판정·재작성 프롬프트의 심사 대상 펜싱 (실측 재검증과 세트로 후속)
- 매수 회고, 거래량 급증 신호(`VOLUME_SPIKE`) 해설, 퀴즈 주제 시드 (파킹 — `AI-2-1.3`)
