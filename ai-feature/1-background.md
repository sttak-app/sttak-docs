# AF-1. 배경과 문제 정의 (배치 AI 기능)

이 디렉터리(`docs/specs/ai-feature/`)에서는 배치로 생성하는 세 가지 AI 기능인 학습 퀴즈,
차트 신호 해설, 매매 회고를 다룬다. 뉴스 AI(요약·호재/악재 판단)와 챗봇은 같은 데이터를
사용하므로 `../ai-chatbot/`에서 함께 설명한다. 모든 기능은 같은 가드레일(검증 파이프라인)을
사용하며, 관련 용어와 기본 원리는 `../ai-chatbot/1-background.md`의 용어집을 따른다.

## AF-1.1 해결하려는 문제

sTTak은 초보 투자자를 위한 주식 학습 서비스다. 차트 신호와 사용자의 매매 기록은 계속
쌓이지만, 기록만 보여 주어서는 학습에 도움이 되기 어렵다. 각 기능은 이 데이터를 다음과 같이
학습 콘텐츠로 바꾼다.

| 입력 데이터 | 문제 | AI가 하는 일 | 제공 방식 |
| --- | --- | --- | --- |
| 입력 데이터 없음(순수 생성) | 기초 개념 학습 콘텐츠의 지속 공급 | **학습 퀴즈 생성**: 기존 문항과 겹치지 않는 4지선다 문제와 해설 생성 | 배치 생성 → 저장 → 매일 조회 |
| 차트 기술적 신호 (서버가 룰로 감지) | "골든크로스"라는 이름만으로는 학습이 안 됨 | **신호 해설**: 의미 · 발생 원리 · 이번 발생 맥락 · 균형 감각 | 신호 감지 시 1회 생성 → 저장 → 조회 |
| 사용자 모의 매매 기록 | 결과(손익)만 확인하고 판단 과정을 돌아보지 않음 | **매매 회고**: 매매 근거(rationale)를 중심으로 잘한 점, 점검 질문, 학습 주제 제공 | 매도 정산 후 1회 생성 → 저장 → 조회 |

세 기능은 모두 배치(경로 B)에서 이벤트당 한 번만 생성해 저장한다. 사용자가 조회할 때는
저장된 결과만 읽으므로 LLM을 호출하지 않는다. 이 점이 실시간으로 동작하는 챗봇과 다르다.

## AF-1.2 핵심 제약: 투자 권유 금지

sTTak은 학습 서비스이므로 AI 생성물에 투자 권유로 읽힐 수 있는 표현이 들어가면 안 된다.
다만 다음과 같이 교육과 권유의 경계가 모호한 경우가 있다.

- 회고에서 쓰는 "다음에는 매수 전에 기준을 정해보세요" 같은 문장은 교육 목적이지만
  '매수'라는 단어를 포함한다.
- 차트 해설은 신호의 의미를 설명해야 하지만, 사용자가 이를 매매 시점에 대한 조언으로
  받아들이게 해서는 안 된다.
- 단순한 단어 필터만으로는 이 경계를 구분하기 어렵다. 따라서 모든 결과물은 저장하기 전에
  **가드레일 검증 파이프라인**(무조건 재생성 → 검수)을 거친다. 파이프라인의 기본 원리는
  `../ai-chatbot/`과 같으며, 각 기능에 적용하는 방법은 `3-1`에서 설명한다.

## AF-1.3 도메인 용어

가드레일과 검증에 공통으로 쓰는 용어(재생성, 검수, 후보 탐지, 코드 잠금, 소진, 오탐,
refusal, 프롬프트 주입) 및 실행 구조 용어(경로 A/B, 멱등)는
`../ai-chatbot/1-background.md`의 용어집을 따른다. 여기에는 배치 AI 기능에서만 쓰는 용어를
정리한다. `업계`는 일반적으로 쓰이는 용어, `sTTak`은 이 저장소에서 정한 용어를 뜻한다.

| 용어 | 정의 | 구분 |
| --- | --- | --- |
| **기술적 신호 (Technical Signal)** | 가격·이동평균 등 차트 데이터에서 규칙으로 찾는 패턴(골든크로스 등). 서버가 규칙에 따라 신호를 감지하고, AI는 감지된 신호를 설명하는 역할만 맡는다 | 업계(역할 분담은 sTTak) |
| **신호 해설 (Signal Explanation)** | 감지된 신호마다 한 번 생성하며, 생성 후에는 바꾸지 않는 해설 | sTTak |
| **고정 설명문** | "5일선이 20일선을 상향 돌파"처럼 신호별 감지 조건을 미리 작성한 설명. 모델이 감지 조건을 임의로 만들지 않도록 프롬프트에 함께 넣는다 | sTTak |
| **매매 회고 (Trade Retrospective)** | 매도 정산 후 사용자의 판단 과정을 돌아볼 수 있도록 생성하는 글 | sTTak |
| **매매 근거 (Rationale)** | 사용자가 주문할 때 직접 작성한 자유 형식의 글. 회고에서 가장 중요하게 평가하며, 배치 AI 기능 중 사용자가 직접 작성해 프롬프트에 들어가는 유일한 입력이므로 프롬프트 주입을 방어해야 한다 | sTTak |
| **evaluations** | 회고에서 rationale 자체를 평가한 항목 목록(GOOD/BAD/IMPROVEMENT). 항목 수와 타입 순서는 코드 잠금 대상이다 | sTTak |
| **정답 유일성** | 4지선다 문제에서 정답이 명확하게 하나로 정해지는 성질. 오답은 그럴듯해야 하며 선지 길이도 비슷해야 한다 | sTTak |
| **유사도 중복 차단** | 새 퀴즈 문항을 기존 문항 임베딩과 비교해 의미가 겹치면 폐기·재생성하는 것 | sTTak |
| **불변 콘텐츠 (Immutable)** | 한 번 생성하면 수정하지 않는 결과물(신호 해설·회고). 생성에 실패한 건만 다음 배치에서 다시 처리한다 | sTTak |
