# AI-1. AI 기능 배경과 문제 정의

> 본 디렉터리(`docs/specs/ai-feature/`)는 챗봇을 제외한 **배치 생성형 AI 기능 5종**(뉴스 호재/악재
> 판단 · 뉴스 요약 · 학습 퀴즈 생성 · 차트 신호 해설 · 매매 회고)의 스펙이다. 판단과 요약은
> 프롬프트·평가·파이프라인 트랙이 전부 분리된 별개 기능이다 — 어댑터 1개 안에서 각자의
> 트랙(생성→재작성→판정)을 독립적으로 거친 뒤 병합·저장된다(`AI-3-1.2`). 챗봇은 RAG 재설계와 함께
> `docs/specs/ai-chatbot/` 에서 별도 정의한다. 서비스 전체 배경은 `../1-background.md` 참조.

## AI-1.1 왜 AI 가 생성하는가

sTTak 은 20~30대 초보 투자자를 위한 **주식 학습** 서비스다. 학습 콘텐츠의 원료(뉴스 기사,
차트 신호, 사용자의 매매 기록)는 계속 흘러 들어오지만, 그 원료는 초보가 소화할 수 있는 형태가
아니다:

| 원료 | 문제 | AI 가 하는 일 |
| --- | --- | --- |
| 뉴스 기사 (Naver 검색 API) | 전문 용어·긴 문장 — 초보가 못 읽음 | **뉴스 요약**: 쉬운 제목/한줄/상세 + 용어 풀이 1~3개 |
| 뉴스 기사 (같은 원료) | "내 종목엔 뭐가 되는 건지" 해석 부재 | **뉴스 호재/악재 판단**: 종목별 POSITIVE/NEGATIVE/NEUTRAL + 근거(reason·whyPoints) |
| 차트 기술적 신호 (서버 감지, ADR-020) | "골든크로스"라는 이름만으로는 학습이 안 됨 | 신호의 의미·발생 원리·이번 발생 맥락·균형 감각을 4~5문장 해설 |
| 사용자 모의 매매 기록 | 결과(손익)만 보고 과정을 복기하지 않음 | 매매 근거(rationale) 중심의 회고 — 잘한 점·점검 질문·학습 주제 |
| (원료 없음 — 순수 생성) | 기초 개념 학습 콘텐츠의 지속 공급 | 4지선다 학습 퀴즈 생성 (유사도 중복 방지, ADR-019) |

공통 성격: **전부 배치(경로 B)에서 이벤트당 1회 생성 → DB 저장 → 조회 시 LLM 호출 0회.**
사용자 요청 경로(sttak-api)는 저장된 결과만 읽는다 (`../3-1-server-architecture.md` 두 갈래 구조).

## AI-1.2 핵심 제약 — 투자 권유 금지

학습 서비스라는 정체성과 인공지능기본법 대응(CON-S5) 때문에, AI 생성물에는 **투자 추천성
표현이 있어서는 안 된다**(FR-G3, U19). 단순한 금지가 아니라 긴장 관계가 있다:

- 감성 판정의 근거("실적 개선이 기대된다")는 **판정 그 자체**라 중화하면 기능이 죽는다.
- 회고의 코칭("다음에는 매수 전에 기준을 정해보세요")은 **교육적 문장**인데 "매수"를 담는다.
- 이 경계를 부분 문자열 필터로 판별하는 것은 실측으로 불가능함이 확인됐다(정상 834건 중
  68건 오탐) → **2단 가드레일 파이프라인**(ADR-032)이 이 문제의 답이다. `AI-3` 참조.

## AI-1.3 도메인 용어

| 용어 | 정의 |
| --- | --- |
| **가공 (Enrichment)** | 뉴스 원료에 요약·판단 두 트랙을 독립 실행 후 병합하는 배치 단계. 상태머신 COLLECTED→ENRICHED (ADR-003) |
| **호재/악재 판단 (Sentiment)** | 기사 1건 × 종목 1개에 대한 POSITIVE/NEGATIVE/NEUTRAL 판정 + reason + whyPoints. "감성"이라고도 부른다 |
| **신호 해설 (Signal Explanation)** | 감지된 차트 신호 1건당 1회 생성되는 불변 해설 (ADR-025) |
| **매매 회고 (Trade Retrospective)** | 매도 정산 후 생성되는 판단 과정 복기 — summaryLine, goodPoints, watchPoints, evaluations (ADR-024) |
| **매매 근거 (Rationale)** | 사용자가 주문 시 적은 자유 텍스트. 회고의 핵심 평가 대상이자 **유일한 사용자 유래 프롬프트 입력**(주입 방어 대상) |
| **가드레일 (Guardrail)** | 투자 추천성 표현을 차단하는 저장 전 파이프라인 — 무조건 재작성 → LLM 판정 → 피드백 루프 (ADR-032) |
| **재작성 (Rewrite)** | 1차 생성물을 가드레일 11범주 + 형식 슬롯 기준으로 다시 쓰는 LLM 호출. 항상 수행 |
| **판정 (Judge)** | 재작성본의 위반 여부를 LLM 이 pass/violations(category·quote) 로 판정. 최종 판단자 |
| **후보 탐지 (Candidate Detection)** | 룰 엔진(`InvestmentGuardrail.detect`)이 패턴으로 위반 후보를 찾아 판정 프롬프트에 싣는 힌트. 최종 판정이 아니다 — "패턴 위반은 반드시 검토된다"는 결정적 보장 역할 |
| **오탐 (False Positive)** | 정상 문장(코칭·부정 문맥·교육적 언급·인용·사실 보도)을 위반으로 잘못 잡는 것. 가드레일 품질의 제1 지표 — 위반 검출보다 오탐 0 유지가 우선 |
| **경계 문장** | 위반 어휘를 담았지만 위반이 아닌 문장 ("신용 써서 몰빵하기**보다**…"). 검증기 정확도를 가르는 시험대 — 룰 50% vs LLM 86% 의 그 22건 |
| **형식 슬롯 (Format Slot)** | 기능별 출력 규격(문체·길이·불변 필드)을 재작성 프롬프트에 붙이는 조각 (`GuardrailPrompts.*_SLOT`) |
| **코드 잠금 (Code Lock)** | 재작성이 건드리면 안 되는 구조화 값(감성 라벨·퀴즈 정답·회고 평가 타입)을 코드 레벨 동등성 검증으로 잠그는 이중 방어 |
| **소진 (Exhausted)** | 피드백 재작성 상한(2회)까지 위반이 남은 상태. 저장하지 않고 폴백 — `sttak.ai.guardrail.exhausted` 메트릭의 그 소진 |
| **폴백 (Fallback)** | 소진·반려 시 저장하지 않고 취하는 기능별 대체 행동 — 다음 배치 재생성 or 정적 카피 |
| **조건부 모드 (conditional)** | 판정 먼저·위반 시에만 재작성하는 비용 절감 모드 (`sttak.guardrail.mode`). 기본은 무조건 재작성(always-rewrite) |

## AI-1.4 히스토리 요약 (왜 지금 모습이 됐나)

1. **ADR-003/004 (6월)** — 뉴스 가공 파이프라인 + 제공자 스위치(anthropic|openai). 가드레일은
   "프롬프트 지시 + 금지어 부분 문자열 필터" 2겹.
2. **ADR-019/024/025 (7~8월)** — 퀴즈·회고·차트 해설이 같은 "이벤트당 1회 생성" 패턴으로 합류.
3. **SCRUM-73 (8월)** — AI 품질 2차 평가. 기존 가드레일 2겹 모두 결함 실측(오탐 68/834,
   경계문 정확도 50%). 모델은 체급이 지배(소형 47~56% vs 상위 80~83%)함을 확인, luna 로 수렴.
4. **ADR-032 / SCRUM-88 (9월)** — 2단 가드레일 파이프라인 운영 반영 + luna 단일화.
   차트·회고는 이때 openai 환경에서 처음 활성화됨(종전 Claude 전용 구현이라 비활성이었음).
5. **뉴스 트랙 분리 (9/14, PR #53)** — 운영 반영 때 병합됐던 요약·판단 프롬프트를 검증된
   단독 문안(v2/v4)으로 되돌리고 파이프라인 트랙도 분리(검증-운영 정합 복원). 병합본은
   병합 형태로 실측된 적 없는 미검증 델타였고, v4 조항 3블록 누락도 이때 발견·복원.
